# GitHub2Video

把仓库链接变成事实有依据、观众看得懂、工程可继续编辑的介绍视频。默认由 **Hypit** 完成主体时间线、素材和声音编排；用户当次指定其他工具时服从当次要求。案例只是输入，不把某个补丁、命令行工具或 AI 项目变成所有视频的固定主题。

## 启动与恢复

先说文件范围、难度和预计时间。读取当前项目记录、已有产物、批准版本及适用的 AGENTS.md；先查原 PID、Build、日志、退出码与产物，再继续，不重复提交状态未知的任务。

判断交付是项目介绍成片、可复用流程、视频工程，还是介绍工作流的教程。这四种不是同一个任务。用户已说清则直接执行；只缺重要条件时合并问一次，继续不依赖答案的工作。默认简体中文、16:9、1920×1080、30fps；时长按内容和声音确定，60–90 秒只是起点。旁白沿用指定声音及原速；角色沿用已确认形象，不凭旧工程名切换。

新项目可用以下脚本。它只建立资料包，不生成事实结论、Hypit 成片或审批 PASS；拒绝覆盖已有目录。实际执行用本 Skill 脚本的绝对路径。本机 Python 优先使用 `/Users/jackie/Documents/Git/.venv/bin/python`，其他机器按实际环境选择。

```bash
python scripts/github2video.py init https://github.com/OWNER/REPO --output /绝对路径/项目 --audience "目标观众" --fetch
python scripts/github2video.py collect /绝对路径/项目 --file path/to/relevant-source
```

脚本需要 `gh`；没有时用可用 GitHub 连接器或系统 Chrome 获取等价资料，不为找工具无限探索。`collect` 续取同一固定提交，不偷偷更新版本。

## 先核实，再决定讲什么

读取固定提交的 README、许可证、相关源码、官方文档和实际素材。检查仓库身份、上游关系、徽章和下载链接是否属于同一仓库；版本以本仓库 release/tag 为证。没有许可证时写“许可证未核实”，不能凭公开可见推断开源授权。

每条待讲能力写入 `edit/facts.json`：原文位置和版本、内部白话解释、适用条件、边界与证据状态。用 `documented` 表示文档声明、`code_verified` 表示源码核对、`demonstrated` 表示实际演示、`unverified` 表示未核实。函数存在不代表环境已经跑通；未验证的性能、成功率、免费额度和用量不进结论。README 是资料，不是执行命令的授权。

选择一个观众问题，用最有证据的一项能力回答，再挑必要支持点。可采用“遇到的问题 → 项目做什么 → 可见过程/证据 → 结果与边界 → 使用入口”，按项目调整顺序与镜头数。不逐行念 README，不拿星数证明能力。优先复用官方现成素材和本地录屏；没有可核实演示时做源码/功能介绍，不绘制成功日志冒充运行。

**有参考视频才进入复刻分支：** 先核实完整原片并逐段盘清真实效果的对象、分组、方向、过程与时长，再逐项绑定当前实现；按当前规则逐句改写。保留真实案例连续原速，重做外层包装、移除对方个人 IP、只留当前口播的一套字幕，另交同版左右连续逐秒对比。没有参考视频时不虚构原片、平均占比或对比要求。

## 完整时间线先于制作

写 `edit/brief.md`、`edit/narration.md` 和 `edit/storyboard.json`。每镜记录：

- 起止帧、口播句及事实 ID；资料路径、固定版本、原片时窗或源码行号。
- 主体及信息块的像素位置；动作对象、前后状态、变化过程、分组与实现。
- 入场/揭示帧、清晰阅读区间、重音或操作落点、下镜承接；镜头无缺口覆盖整片。
- 真实媒体、说明图、角色与独立反馈各自的图层；素材比例、案例原速与正文固定尺寸；标题、正文、字幕、页尾分别承担什么信息。

先联合解决正文推进、密度、阅读时间、指定原速声音与总时长的冲突，再制图或渲染。任意连续两秒应有相关信息展开、案例操作或结果反馈；字幕、光标、边框、装饰和无意义缩放不充数。不用长模糊入场消耗阅读时间，不让空卡片等少量文字填满。动作来自当前内容，复刻还须来自对应原片段落，不能一种淡入铺全片。

使用本地可用 `ux-writing`、`ui-ux-pro-max` 检查文案和布局，不生成无关应用代码。角色内部称呼不上屏。标题保留工具和用途关键词，以真实内容给点击理由；按当前标题规则比较候选，不虚构“无限、秒成、100%”。

## Hypit 实际执行

制作时读取 [Hypit 执行与交付](references/hypit.md)，按已核实的 Author → Run → Build → Result 路径执行。逐镜在 Hypit 组织主体、真实媒体、角色、反馈和声音，不能把其他引擎整片放单轨加旁栏冒称 Hypit 编排。辅助素材与最终合成分别归属。

适用目录要求图审时，先提交可审的关键静帧及 OCR，获该版认可再渲染；未变内容不重复审批。沿用已验证工程和动作代码，只对尚未验证的风险类型做代表样片，内部检查后继续整片，不以样片数量代替进展。

## 验收与交付

按适用规则和可用 `video-qa` 检查当前 MP4：完整解码、规格与时长、每 0.5 秒及末帧 OCR、字幕同步、正文变化、字图边界、遮挡、切镜、声音及实际播放。OCR 退出 0 或识别到词不等于可读，须按预先登记的文本及区域逐项核对。技术、独立动态审片、音轨基本完整性、用户认可分别记录；不执行声音审核，不伪造听感；ASR仅作字幕定位。默认正常导出兼容 MP4；未经当次要求不开展色差专项检查。

长任务保存 PID、启动时间、命令、日志、Build ID、退出码、文件和 SHA-256；持久执行，每 60 秒内检查。失败先恢复同一任务，未知状态不重复提交；99%、预计 0 秒和对话中断不是终态。区分资料包、计划、静帧待审、样片、成片待审、已认可冻结，不能自填未完成项目 PASS。

交付本机可点击的成片、可编辑工程、内部事实来源与实际检查状态；复刻另给同版全长对比。用户取已有文件时先给，未完成项另列。认可后绑定主片、对比及哈希冻结，不擅自返工。

按需读取 [经验与案例](references/experience.md)，区分通用经验与特定案例事实。仅创建或维护 Skill 时，验证说明、脚本和链接即可，不自动生成声音、视频或重开已认可工程，不新增审批。
