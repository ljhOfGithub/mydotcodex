# AI 口播成片生产流水线

交付目标不是“加了几个素材”，而是一条叙事顺、声音连续、画面有节奏、可继续编辑且经过实际导出验收的口播成片。默认简体中文、保留原文件、不发布、不购买会员。

## 先判断任务从哪一段开始

- 只有主题或想追热点：先使用 `ai-hot-video-script-collector`，得到有来源映射的原创口播稿。
- 已有稿件但还没拍：交付拍摄版稿件，标出停顿、重音、可插画面和预计时长；不要直接假设已经有原片。
- 已有原片：从媒体体检、本地转写和剪辑设计开始。
- 已有原片且希望不靠本人训练来改善普通话、语气或语速：先读取 [references/local-voice-redub.md](references/local-voice-redub.md)。首次合作先交付同内容、同响度的短段 A/B 试听；用户已经建立持久声音默认时，后续完整成片直接沿用该选择，不得静默退回原声。
- 只有一条构图简单的真人口播、希望升级为动态成片：先读取 [references/simple-talking-head-dynamic-editing.md](references/simple-talking-head-dynamic-editing.md)，按其中的录制输入、语义配画、布局状态机和 Premiere/剪映路线执行。
- 用户要求“更成熟”“减少模板感”“按专业短视频审美继续精修”，或需要解决留白、静态信息页、标题常驻、转场叠影与手机端可读性时，必须读取 [references/editorial-aesthetic-qa.md](references/editorial-aesthetic-qa.md)。
- 用户提供参考视频并要求字幕“更有重点”“自动高亮”或复刻其强调方式时，必须读取 [references/semantic-caption-highlighting.md](references/semantic-caption-highlighting.md)。先拆解参考样式与触发逻辑，再交付 5–12 秒样片；未经样片确认，不得直接套用到完整成片。
- 已有粗剪：先诊断节奏、转场、音频、字幕和 B-roll 是否与口播语义匹配，再做窄改。
- 只要封面：使用 `ai-script-cover-generator`，不启动整条视频流水线。

## 开始前必须给出的信息

1. 难度、预计耗时、输入文件绝对路径、预计新建或修改的文件。
2. 本轮目标：完整成片、前 30 秒样片、粗剪、精修或只做诊断。
3. 编辑器路线：剪映、Premiere，或“确定性预合成 + 剪映最终草稿/导出”的混合路线。
4. 明确不会覆盖原片；可能产生付费、登录、上传或发布时，提前说明边界。

用户没有给非关键偏好时，默认 9:16、45–90 秒、原人声连续、3–5 个关键视觉节点、克制字幕和一种主转场，不停下来追问。视觉节点不等于全部使用 B-roll：场景用 B-roll，关系、分类和流程优先用透明动态图形。

## 核心工作流

所有原片加工统一使用四个状态，避免把中间结果说成成片：

- `planned`：只有镜头表和素材计划；
- `draft`：已经合成，但未完成逐点检查；
- `preview-verified`：样片的媒体规格、语义画面和转场已检查；
- `final-verified`：完整视频已独立导出并通过最终验收。

### 此工作区已确认的声音默认

- 完整真人口播成片默认使用本地 Qwen3-TTS 本人音色重配，声音方向为用户已经选定的 `B 自然重配`；除非用户在当前任务明确要求保留原声，否则原声只能作为 A 版对照，不能作为终版音轨。
- 用户明确要求更强的轻重、长短、缓急或情绪时，只能在本人原声或直接本人音色克隆上做逐句分段、标点、候选筛选和局部节奏设计。禁止先用第三方预设说话人生成表演轨，再转换成本人音色；陌生口音、咬字或说话习惯不能因为正文转写正确而放行。
- 短样片、纯视觉测试或只做诊断时可以保留原声，但必须在文件名和汇报中标明“未重配音色”。
- 每个完整项目保存 `voice_delivery.json`，并在终版前运行 `scripts/validate_voice_delivery.py`。校验未通过时，项目最高只能标为 `preview-verified`。
- 重配改变语速和句长后，先锁定正式音轨，再重建字幕和视觉时间码；不得把原字幕直接套到新音轨。

### 1. 建立事实基线

- 用 `ffprobe` 记录源文件时长、分辨率、帧率、视频/音频编码和声道。
- 抽查开头、正文、结尾，确认画面方向、清晰度、字幕是否已烧录、是否存在黑帧或音画漂移。
- 在独立编辑目录保存 `project.md`，记录源文件、目标、时间点、草稿、终版和验收结果。
- 用户引用旧对话、旧项目或既有流程时，先盘点可复用资产并保存 `asset_inventory.md`。必须列出真实存在的透明动画、录屏、B-roll、字幕和草稿；不能只复用最容易找到的一类素材。

### 2. 先剪内容，再装饰画面

- 有明显口误、重复、口癖或长停顿时，优先使用本地逐字转写生成可审查的 `content_plan.json`；不能仅凭波形盲剪。候选包括“嗯、呃、啊、呀”等填充音和紧邻的无声停顿，但这些字承担语气、列举或句意时必须保留。
- 逐词转写后还必须生成 `cadence_review.json`：列出句内词间隔、起音失败、半词/音节重复、拖长元音、连续换气和不自然停顿。独立语气词为 0 不等于节奏通过；ASR 没有输出重复 token 时，仍要检查长于约 0.35 秒的句内空隙和局部波形/听感。
- 单个汉字的 ASR 时间戳异常长（通常超过约 0.6 秒）时，不得直接把整段当作有效发音；必须用 `silencedetect`、局部 RMS 或波形复核真实起音/收音边界。若 ASR 把静音并入相邻实词，剪点以声学边界为准，并保留约 0.18–0.30 秒自然换气。
- 删词必须同时剪视频和音频；源片已有烧录字幕时尤其不能只静音，否则会留下字幕和口型。先运行 `scripts/render_content_plan.py <content_plan.json>` 生成内容粗剪主线，再重算所有画面时间码。
- 内容粗剪后必须再次逐词转写：目标口癖仍出现、相邻实词丢失、句子变义或剪点出现爆音/吞字时，不得进入配画阶段。源片是烧录字幕时，还必须抽帧确认删除的字不再可见；若字幕句块跨过剪点仍有残留，要局部遮盖并重建该句字幕，不能只以音频转写为准。
- 字幕以原片句界和人工确认的原话为事实基线，不得为了排版把原本不同句块合并。建立专有词与易错同音词表，逐项核对字幕、卡片和动画中的重复文案；ASR/OCR 只能提供候选，不能把“脱敏”之类术语擅自改成同音错字。
- 字幕高亮只改变同一字幕块内的视觉强调，不得改字、改句界或改时间码。默认每块至多高亮一个连续语义锚点，也允许整块不高亮；不得把填充词、连接词或整句话随意着色。
- 每个删点必须保留语义、呼吸和句尾，先做声音连续的口播主线，再规划 B-roll、字幕和放大。
- “更有网感”不能只做统一提速。必须建立语义节奏表，至少区分钩子、步骤编号、信息列举、核心结论和 CTA，并分别记录速度、轻重和停顿策略；关键结论通常比列举更慢、更重，列举可更快、更短。最终同时用逐词转写和独立音频能量扫描验收，不能再用 ASR 词间距代替真实静音检测。
- 对已启用本人音色重配的项目，`cadence_review.json` 中确认删除的卡顿直接从正式目标稿和逐句停顿设计中移除；画面也必须按新音轨逐句重排，不能只换声音而保留旧卡顿时长。
- B-roll 只覆盖场景、案例或操作，不要每句话都插。关系、分类和流程优先交给透明动态图形。60–120 秒视频通常使用 3–5 个关键视觉节点，每段约 1.5–3.5 秒。
- 镜头表使用内容粗剪后的输出时间线；不得直接沿用源片时间码。每次改变内容剪点后，先重算镜头表，再合成画面。

### 2A. 锁定本人音色正式音轨

- 完整成片在内容稿确认后、视觉时间码确定前，按 [references/local-voice-redub.md](references/local-voice-redub.md) 逐句生成 `B 自然重配` 正式音轨。
- 保留原声 A 版用于比对；不得用简单全局拉伸冒充 B 版。逐句候选需检查错词、尾部重复、目标口癖和自然停顿。
- 用户在当前项目明确否决现用 TTS 的机械感、伪语气词或口型偏差时，视为对该重配方案的明确退出：保留失败候选，不得继续复用同一模型；可改用本人原声的语义切分、分段同速音画节奏调整和线性响度校正，并在 `voice_delivery.json` 记录退出原因。
- 正式音轨确定后重新转写、重建字幕时间码，再规划人物回场与 B-roll。真人嘴部清晰可见的区间必须检查口型；不同步时应调整镜头或用有语义的画面覆盖。
- 在 `voice_delivery.json` 记录模型、参考音频、正式音轨、二次转写、字幕、响度/真峰值和口型状态。`scripts/validate_voice_delivery.py` 通过后才能进入最终导出。

### 3. 选择可信画面

先把画面分成四层，镜头表必须明确写出层级，不得把“转场”当作“动画”：

1. `speaker`：真人主线，负责信任、判断和普通连接句；
2. `broll`：真实录屏、工作材料或场景画面，负责展示“它长什么样、在哪里发生”；
3. `motion_graphic`：透明关键词、分类卡片、关系图或流程图，负责解释“重点是什么、彼此什么关系、步骤如何推进”；
4. `transition`：只控制画面如何进入和退出，不承担新的语义。

当文案同时出现对比符号、两个以上并列对象、先后流程或因果关系时，至少评估一次 `motion_graphic`，不能自动退化为又一段通用 AIGC B-roll。已有透明动画与当前语义相符时，优先复用，不得无理由重做或漏用。

优先级从高到低：

1. 真实软件操作录屏或真实工作材料；
2. 可核对的表格、文档、流程和现场画面；
3. 关键词卡片、图示或确定性动画；
4. 只用于补氛围的 AIGC 素材。

画面必须回答当前口播句子，不得添加不存在的公司、数据、案例或功能。AIGC 人物素材过多会削弱真人培训账号的可信度。

参考视频只允许提供布局、节奏和动效规则。当前口播说“比如这次”或展示“本片实际使用的状态”时，示例画面必须来自当前项目本身；不得把参考视频、旧项目或另一条视频的案例截图嵌入成当前案例。无法取得当前素材时，改用当前人物帧、自制信息图或纯文字结构图，并在验收时单独抽查该段。

文案自动配画面时，不是“每句都生成视频”。逐句判断：

- 有真实界面、材料或流程：优先录屏或实拍；
- 需要解释关系：使用关键词卡片、流程图或透明动画；
- 只有难以拍摄的抽象场景：才生成统一风格的 AIGC 画面；
- 普通过渡句、个人判断和结论：保留真人，维持信任感。

默认 AI/B-roll 画面占整条视频约 20%–35%，相邻 B-roll 之间至少回到真人 1 秒。只有连续操作演示才允许连续覆盖。

当参考视频采用“全屏真人 ↔ 信息主画布 + 真人小窗”的演示型构图时，不要退化为全屏人物上不断贴图。先读取 [references/reference-led-layout.md](references/reference-led-layout.md)，把人物状态、主画布模板、身份浮标和回场节奏写进镜头计划。身份浮标只能使用用户明确提供或已核实的信息。

真人竖屏构图出现大面积头顶留白时，先判断人物眼线、手势和平台安全区，不要靠常驻总标题机械填满：

- 系列总标题默认只用于开头约 2.5–3.5 秒；正文回到真人时，不重复同一个总标题。上方区域改用与当前口播对应的短关键词、步骤号或章节名，并在语义结束后退出。
- 需要保留偏小半身比例、且用户已否决人物放大时，优先用当前语义标题或信息卡使用头顶空间。只有能通过主体蒙版或自然画外区域独立移动人物时，才可上移约 5%–8% 画高；禁止对整帧裁顶后用镜像、反射或复制像素填补底边。不得裁头、切下巴、断腕或放大脸部。
- 同一时刻只保留一个上方主标题。系列总标题、章节标题、信息画布标题和 CTA 按语义互斥，不能靠透明度或错开几像素制造双标题。
- 信息画布不得首帧一次性展示全部节点后静置；按口播逐项进入或高亮当前项，结束时再恢复完整结构。卡片数量、顺序和口播必须一致。
- 验收至少抽查开头标题退出、普通真人段、章节标题段、信息页每次内部变化、CTA 和所有人物/画布切换点。

### 4. 让转场服务语义

- 默认采用 0.2–0.4 秒叠化，或轻微推近/缩放；同一条视频尽量只用一种主转场语言。
- 原人声保持连续，优先用画面覆盖形成 J-cut 感，不因切 B-roll 打断人声。
- 进入 B-roll、完全显示、退出 B-roll 三个阶段都要可见；不得用硬切伪装成“已加转场”。
- 动态图形必须检查“进入、信息稳定可读、退出”三个阶段；只有素材整体淡入淡出而没有信息运动、关系变化或分步呈现，只能称为素材动效。
- 片头钩子、普通正文、结论段要有强弱差异，不要全程同样密度。

### 5. 选择编辑器路线

- 默认本地快速交付：使用 `ai-talking-head-jianying-workflow`。
- 用户指定 PR，或需要多轨精确时间、关键帧、复杂音频/调色时：使用独立 Premiere 工程。
- 旧版剪映多轨导入不稳定、素材出现不支持或精确转场难以可靠复现时：先确定性预合成画面并保留连续原音频，再把单一成片导入全新剪映草稿完成最终导出。

混合路线必须如实汇报：哪些剪辑由预合成完成，哪些步骤在剪映完成。不得把“从剪映导出”说成“所有转场均在剪映原生制作”。

使用可审查的 JSON 镜头计划时：

1. 有内容删点时先运行 `scripts/render_content_plan.py <content_plan.json>`，并对输出二次转写验收；
2. 再运行 `scripts/validate_visual_plan.py <plan.json>`，检查路径、时间范围、重叠、真人回场间隔，并分别统计 B-roll、动态图形和总视觉占比；每个视觉项填写 `kind: broll` 或 `kind: motion_graphic`；
3. 最后运行 `scripts/render_visual_plan.py <plan.json>`，生成以内容粗剪为源的预合成样片；
4. 预合成只可标为 `draft`，抽帧和媒体检查通过后才升级为 `preview-verified`。

计划包含 SRT 时，脚本优先烧录字幕；如果本机 FFmpeg 缺少 `subtitles` 滤镜，则明确降级为 MP4 软字幕轨。软字幕可能被平台忽略，正式发布前必须在剪映/PR 重新生成字幕，或换用支持 libass 的 FFmpeg 烧录。

### 6. 独立导出与验收

- 每次使用新的草稿和唯一文件名；失败输出保留并明确标记，不覆盖原片或上一次有效成片。
- 剪映或 PR 界面显示导出成功只是一个信号，不能单独证明交付完成。
- 最终验收必须同时包含：文件存在、`ffprobe` 可读、视频流和音频流存在、时长/分辨率/帧率符合预期、关键 B-roll 中点正确、每段动态图形的信息稳定帧正确、每个进入/退出至少检查“前/混合/后”三帧、音频连续。
- 使用专项剪映 skill 的 `scripts/verify_video.sh` 生成媒体信息、关键帧和联系表。
- 透明关键词动画优先使用经本机验证的 `qtrle/ARGB MOV`；不要默认假设 VP9 alpha 能被当前 FFmpeg 解码链正确合成。静态图轻推拉只能称为动效，不能称为图生视频。

### 7. 生成独立封面

完整成片任务中，用户要求封面或平台交付需要封面时，封面是独立交付物，不得把视频第一帧或一张未检查的生成图当作终版。

- 先读取 [references/cover-workflow.md](references/cover-workflow.md)，再使用 `ai-script-cover-generator`。
- 标题只来自已定稿文案或成片主张，默认一个冲突、两层字号、一个强调色；不添加无根据的数字、头衔或品牌。
- 需要真人封面时，从用户有权使用的无字幕原片选 4–6 帧，人工选出睁眼、头部完整、面部清楚的一帧。
- 文字错误时只允许一次定向生成修复；仍错时输出无字背景，再用本地字体确定性排版。
- 小红书默认交付 1080×1920 PNG，检查上下安全区、字序、缩略图可读性、人脸一致性和头顶完整性。
- 封面默认不烧入视频；平台发布与视频首帧是两个不同交付面。

详细的目录、转写、编辑器路由、失败症状和验收清单见 [references/editing-playbook.md](references/editing-playbook.md)。执行原片加工或排查失败导出时必须读取该文件；只做脚本或封面时不读取。

## 交付标准

最终汇报必须区分：

- 实际完成的内容变化；
- 编辑器内草稿状态；
- 真实导出并验证的终版；
- 没有完成或因付费/登录限制跳过的功能；
- 原片、项目记录、草稿、终版和验收图的绝对路径；
- 如本轮包含封面，报告封面绝对路径、尺寸、主标题、人物帧来源和文字验收结果；
- 是否发生登录、购买、上传、发布、覆盖或环境修改；
- 如本轮包含本人音色重配，分别报告原声、自然生成、节奏匹配或其他候选的时长、二次转写结果、响度/真峰值、是否完成口型同步，以及用户最终选择的版本；不能用“转写正确”代替“普通话达到专业等级”的主观或专业判断；
- 当前可见的周额度状态；没有任务前快照时，不编造本次精确增量。
