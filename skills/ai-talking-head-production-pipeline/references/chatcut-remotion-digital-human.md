# ChatCut + Remotion 数字人教程剪辑规范

这份参考用于数字人口播、软件教程、真实操作录屏与程序化动效混合的视频。目标不是“把素材摆上去”，而是达到可与用户指定参考创作者逐镜头比较的成片质量，同时把 ChatCut Credits 花在真正需要口型生成的位置。

## 工具分工与事实边界

- ChatCut：管理已有数字人、绑定声音、口型视频、字幕、录屏素材与可编辑时间线；是否消耗 Credits 以实际确认卡、账单或余额记录为准。
- Remotion：负责确定性的逐帧构图、字幕同步、镜头切换、转场、批量渲染与版本复现；本地 Remotion 合成本身不消耗 ChatCut Credits。
- HyperFrames：作为分镜、节奏、动效和转场的审美规则层；除非实际使用其运行时，否则不要把 Remotion 渲染说成 HyperFrames 渲染。
- 生成数字人、口型、TTS、图片、视频或音乐可能消耗 Credits；移动、裁切、缩放、字幕排版、Remotion 合成与本地导出通常不是生成调用。不得把历史价格当作当前价格，必要时现场核对。

## 参考片先行

用户要求对标娜娜、阿东学长或其他创作者时，成片设计前必须建立参考片事实基线：

1. 在用户指定的系统浏览器与既有登录会话中打开准确视频；以标题、URL 中的视频标识和播放器时长三重确认，防止进入相邻视频。
2. 记录钩子、人物全屏、人物小窗、纯录屏、信息卡、转场和结尾的时间点。参考片只提供节奏、构图和动效规则，不得把对方的案例画面伪装成本项目素材。
3. 至少比较：前 3 秒钩子强度、平均镜头/布局变化间隔、人物与主画布占比、录屏可读性、字幕强调逻辑、转场族、结尾收束方式。
4. 用户要求“对标”时，未完成参考片与候选成片的同时间轴对照表，不得把候选标为 `final-verified`。

参考片中的局部取帧必须等待视频 seek 完成并确认实际时间；拖动页面坐标容易误入相邻视频，不能只凭页面外观判断。

## 真实界面捕获与讲解映射

- 录制前先写“旁白句子 → 必须显示的真实界面状态 → 素材文件 → 成片时间”映射。没有对应具体讲解的界面素材不得进入成片；同一张泛化界面不能循环冒充多个不同操作。
- 每次录屏完成后立即检查首帧、中间帧和尾帧，确认前台确实是目标 App、窗口内容与预期一致、没有录到 Codex 或其他窗口。录错应用的片段直接标为不可用，不能靠裁切或模糊掩盖。
- 屏幕录制不可靠时，可以改用目标 App 的原生窗口截图，加确定性的局部放大、焦点标注和缓慢推近；交付时必须如实称为“真实界面截图”，不能说成完成了点击录屏。
- 静态截图只能证明界面当时存在，不能证明某个点击、生成或导入动作已经执行。台词和字幕相应使用“展示入口/界面/位置”，只有连续录屏或可核验操作日志才能使用“点击/生成/导入完成”。
- 当前版本找不到某个按钮、Skill 或入口时，不虚构 UI，也不把“没有匹配结果”画面当成功流程。改用当前真实可见的 Agent 输入区、素材区或其他实际路径，并记录产品版本和降级说明。

## 数字人口播提示词

提示词至少说明：

- 逐字台词，并要求不要改写；
- 语气、重音和节奏；
- 神态自然、正常眨眼；
- 合适的点头、摇头和小幅手势；
- 人物是否保持一致；
- 背景、画幅和分辨率；
- 自然看向镜头。

示例结构：

```text
用这个数字人朗读：“<最终台词>”。不要改写台词。语气自然，重点词适当加重；神态自然，正常眨眼，配合少量点头、摇头和小幅手势。人物保持不变，背景使用<背景>，画面为<画幅>、<分辨率>，自然看向镜头。
```

眨眼、手势和点头是表演指导，不是必然命中的独立参数；生成后必须看连续视频验证，不能只看单帧。

## 先锁音频和字幕，再做画面

1. 盘点已有数字人口型视频、绑定声音、旁白、字幕、真实录屏、图片和旧时间线，优先复用已付费素材。
2. 用实际音频时长建立句级时间轴，不能按文案字数猜时长。
3. 需要压缩时长时，优先评估保持音高的轻度变速或删去重复内容；不要为了几秒差异重复生成整段 TTS。
4. 改变旁白速度或剪点后，重新计算字幕和镜头时间码。
5. 嘴部清晰可见的数字人片段必须使用与该段音频对应的原始口型；不同台词、不同速度或错位音频不得露出嘴部冒充同步。

### 唯一主对白总线

- 正式成片只保留一条主对白总线。Remotion 中承载画面的 `OffthreadVideo` 默认静音；如果数字人片段的原声必须保留，就把该段原声纳入主对白并关闭同区间的独立旁白，禁止两个入口同时发声。
- 不得把长旁白切成多段后，再用明显不同房间感或音色的数字人原声在中间硬插。即使时间线上没有同帧重叠，声线、采样率、底噪和混响突然改变，也会形成“回音、穿插、像两个人抢话”的听感。
- 不用 `1.45×` 一类明显全局提速把长稿硬塞进目标时长。优先删重复、扩展成片时长或逐句轻度调速；关键结论和 CTA 保留自然呼吸。
- 每个对白接缝保留约 0.12–0.25 秒自然停顿，并做 20–30 ms 边缘淡化。SFX 避开字头和字尾；whoosh、impact、riser 不得压住连续口播。
- 正式音频验收不只看 LUFS 和长静音：还要对每个声源切换点检查波形、RMS、接缝 click、局部转写和实际听感。Studio 预览异常不能代替对实际 MP4 的检查。

## 人物状态机

镜头表必须给人物标记以下状态之一：

- `speaker_live_full`：真实连续运动且口型与当前台词一致的全屏/中景人物；用于钩子、关键判断和真正回场。
- `speaker_live_pip`：真实连续运动的小窗人物；不能遮挡主要操作区域。
- `screen_only`：纯录屏或材料画面，由旁白驱动；教程步骤的默认状态。
- `graphic_only`：信息卡、流程或结果卡；承担抽象关系，不假装是真实操作。
- `photo_card`：明确被设计成照片、档案卡或章节封面的静态人物图；必须有照片语义和独立动效，不能在旁白台词下冒充正在讲话。

### “主持人回场”的严格定义

回场是人物从录屏/信息画布后重新成为叙事主体，必须使用连续运动的视频。人物有台词时口型必须对应；人物无台词时也应有自然眨眼、呼吸或手势，并由音乐、停顿或字幕明确其功能。

单张静态真人帧、循环缩放的照片或冻结的视频都不叫回场。尤其禁止在旁白继续时突然摆出静态真人，让观众误以为人物将开口。需要低 Credits 收尾时，优先选择：

1. 纯录屏结果 + 动态结论文字；
2. 已有且台词匹配的动态数字人片段；
3. 把已有同步片段改造成明确的首尾呼应，并保留它的原声；
4. 明确标注为照片卡的设计，而不是主持人回场。

## 教程型分镜

推荐结构不是固定模板，而是一套信息责任分配：

- 开场：动态人物或强操作结果建立信任和问题；
- 任务定义：展示要解决的具体剪辑问题；
- 操作步骤：让真实录屏成为主画布，人物缩小或退出；
- 解释关系：使用步骤号、关键词和流程卡，不用无关氛围 B-roll；
- 修改与检查：展示真实时间线、前后对比或结果；
- 收束：动态人物真正回场，或使用纯结果画面 + 动态结论。

数字人不是全程站台的壁纸。人物何时出现由叙事功能决定：建立信任、发表判断、连接章节时出现；需要读清操作时缩小或消失；没有匹配口型素材时不要为了“有人”而放静帧。

### 可复用教程片头

教程开头优先使用 `痛点一句 → 成果先给 → 时间承诺 → 路线预告`，而不是慢 Logo、背景铺垫或连续大标题：

```text
不会【目标任务】？别急着先学一堆按钮。
先看结果：【三个可见变化】。
给我【明确时长】，我带你用【工具】从【输入】走到【结果】。
整个流程，就【步骤数】步。
```

第 0 帧直接进入问题或结果；成果预览必须来自本项目真实画面。片头模板只约束信息责任，不要求每条视频逐字复用。

## 画面密度和录屏可读性

- 主信息区必须足够大，观众在手机端能看清按钮、输入内容或时间线；不能把完整软件界面缩成装饰缩略图。
- 通过语义裁切、局部放大、步骤编号、关键词和前后对照提高信息密度，而不是堆无功能装饰。
- 高密度教程可把布局变化控制在约 1.5–2.5 秒一个可感知节点，但必须服从台词，不能机械地每两秒切一次。
- 黑/白/浅灰可作稳定基底；品牌紫用于小胶囊、细进度线和短促速度条；黄色用于少量关键词。大面积紫色描边框容易像编辑器选中态，除非精确贴合操作对象，否则不要使用。
- 操作高亮必须指向真实按钮、输入框或时间线位置；无法精确贴合时宁可省略。
- 任一关键帧都应有清楚的主焦点和次焦点。空白只在建立层级或制造节奏时保留，不用装饰性网格掩盖内容不足。

## 转场和动效

- 为同一条视频选择一个主转场家族，例如 editorial push/slide；章节切换才使用更明显的方向变化，结尾可受控淡出。
- 转场前、混合中、转场后都必须可读，不能出现黑边、人物跳位或字幕断裂。
- HyperFrames 可提供 beat slam、marker sweep、motion blur streak、card morph 等规则；实际渲染仍应准确报告为 Remotion 或编辑器输出。
- 动效必须服务语义：关键词出现、步骤推进、画面状态变化。只有整体淡入淡出不等于完成了镜头设计。

## Credits 最小化策略

1. 脚本和人物出场点确认后，再一次性生成必要的动态数字人片段。
2. 生成成功后明确复用现有结果，禁止因排版调整重复生成口型或声音。
3. 纯录屏、字幕、MG、Remotion 转场和本地导出承担主体剪辑。
4. 若缺少匹配的动态结尾，不用静帧冒充；改为纯结果收尾，或让用户确认是否值得增加一次短数字人生成。
5. 汇报时区分生成费用与剪辑费用；没有账单证据时不声称精确消耗。

## 逐帧与参考片级验收

完整成片必须调用 `video-qa`，并把下面门槛作为其补充。只做九宫格、媒体规格或静音检测不能称为最终验收。

### 全帧自动检查

- 对实际导出的 MP4 解码全片，运行黑帧、冻结帧、闪帧、解码错误、边缘异常、长静音和响度检查。
- 冻结检测必须覆盖所有人物出现区间。人物静止但字幕或背景仍在动时，仍要单独对人物 ROI 或源素材状态检查，不能让全画面动效掩盖人物冻结。
- 每个转场检查开始前、混合中和结束后连续帧；任何一帧有黑边、越界、字幕跳动或人物位置瞬移，都要修复后重渲染。

### 人工动态检查

- 完整实时播放一遍，听声音并看人物运动，不能静音快进代替。
- 以 0.5–1 秒间隔生成全片接触表，检查信息密度、主体大小、字幕换行和录屏可读性。
- 对每次人物出现、消失、大小变化和转场，生成逐帧条带；至少覆盖前后各 0.5 秒。
- 有真人/数字人的区间逐段确认：是否连续运动、是否眨眼/呼吸自然、当前音频是否与口型对应、人物是否遮挡操作。
- 在 1:1 原始分辨率检查文字和人脸；缩略接触表只能定位问题，不能证明细节正确。
- 用户明确要求“每一帧检查”时，必须让导出的每一帧进入可审查证据，例如每秒一张包含该秒全部 30 帧的 6×5 联系表，并逐张人工查看；只做每秒一帧抽样不能表述为逐帧检查。异常帧再回到 1:1 原始像素复核。

### Remotion 孤立闪屏与平铺马赛克

成片中偶发一帧整屏重复、分块平铺或马赛克时，不要先把它当成转场、素材损坏或播放器问题。按以下证据链区分合成代码错误与并行渲染污染：

1. 从正式 MP4 截取异常点前后至少各 1 秒，并导出该区间全部帧；记录异常帧编号、实际时间和相邻正常帧。30 fps 时可把每秒 30 帧排成 6×5 联系表，但异常帧仍要以 1:1 原始分辨率复核。
2. 直接从同一 Remotion Composition 渲染对应的单帧 still。若 still 与前后帧均正常，而完整 MP4 在相同帧出现整屏重复或分块平铺，优先怀疑并行 Chrome 捕获或编码阶段污染，不要盲目修改转场组件。
3. 先用唯一文件名渲染只覆盖异常区间的短测试片，显式使用系统 Chrome，并设 `--concurrency=1`。测试片必须再次导出全部帧并逐帧检查；不能只看播放时“好像没闪”。
4. 短测试片通过后，以完全相同的浏览器和单并发设置重渲染全片。保留原失败文件并标明症状，不要直接覆盖；新文件通过后再复制或改名为正式路径。
5. 对新全片运行完整解码检查，例如 `ffmpeg -v error -i <final.mp4> -f null -`，并重新导出原异常区间全部帧。只有完整解码无错误、同区间逐帧检查通过，才能升级为 `final-verified`。

一次修复只改变一个关键变量。若请求了不同像素格式但探测结果仍未改变，而单并发版本已消除异常，应把有效证据归因于并发变化，不得虚构为像素格式修复。

### 参考片对标表

至少记录候选片与参考片的：

- 前 3 秒画面变化与钩子；
- 每个章节的布局状态；
- 人物全屏/小窗/隐藏的实际时长；
- 录屏主体占比和操作点可读性；
- 字幕强调频率与关键词逻辑；
- 转场数量、类型和节奏；
- 结尾是否为真实动态收束。

候选片明显低于参考片的可读性、动态连续性或镜头节奏时，状态只能是 `draft`。只有技术检查、全帧检查、人工动态检查和参考片对标均通过，才能写“完成”或 `final-verified`。

## 常见失败及处置

- **静态人物冒充回场**：删除人物静帧；改用纯结果收尾或匹配口型的动态人物片段。
- **画面空**：先放大真实录屏和主体，再增加语义卡；不要先加边框和背景纹理。
- **录屏太小**：按当前台词裁到操作区域，必要时做两级放大或前后对照。
- **大紫框像选中态**：删除大框，只保留贴合真实目标的小标记。
- **旁白全程、人物失去作用**：重新分配人物的信任、判断和章节连接功能；人物出现必须有动态素材支持。
- **为了省 Credits 放静帧**：省 Credits 不能牺牲真实性。没有动态素材就选择 `screen_only` 或 `graphic_only`。
- **抽帧通过但播放奇怪**：说明静态 QA 不足，必须回到实时播放、冻结检测和人物区间逐帧条带。
- **偶发单帧整屏重复或平铺马赛克**：先比较正式 MP4 全帧与同 Composition 的 still；still 正常时用系统 Chrome、`--concurrency=1` 渲染异常区间复现，再以相同设置重渲染全片并完整解码。不得靠删掉异常帧掩盖渲染污染。
- **声音像回音或抢话**：先列出所有可发声组件，确保每个时间点只有一个主对白源；再检查数字人原声与旁白的声线切换、接缝淡化和 SFX 遮蔽，不要只看“代码没有重叠”就放行。
- **为了卡时长粗暴提速**：恢复自然语速，删掉重复信息或延长总时长；重新生成字幕和镜头时间码，不能沿用提速版时间线。
- **结尾只有口号**：CTA 必须写出具体口播、屏幕动作和画面运动；至少明确评论互动、点赞、收藏和关注中的实际动作，背景继续播放真实结果，避免最后 1.5 秒近似静帧。

## 本机已验证路径

- 浏览器预览使用系统 Google Chrome 默认用户目录；不要使用内置浏览器、调试端口或空白 profile。
- Remotion Studio 可复用系统 Chrome 会话。若内置 Headless Shell 出现 `ProtocolError: Target closed`，渲染时显式指定 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。
- Remotion 预览视频优先使用 `OffthreadVideo`；音频使用 Remotion 原生 `Audio`。若 `@remotion/media` 的视频组件在 Studio 触发 Mediabunny `AbortError`，不要继续把预览异常当素材损坏。
- 最终报告必须说明：哪些素材复用、哪些内容新生成、Credits 证据、实际渲染器、视频规格、QA 覆盖范围以及未通过项。
