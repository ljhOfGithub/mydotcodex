# 语义高亮字幕规范

适用于用户提供参考视频，或要求字幕更有重点、更有节奏、自动识别重点词时。目标是复刻参考视频的“强调系统”，不是随机给字幕换颜色。

## 不可变事实

- 原片人工确认的字幕文字、句界与时间码是事实基线。
- 高亮只能在同一字幕块内部切分样式，不得改写、合并、补词或跨块搬运文字。
- 拼接 `前段 + 高亮段 + 后段` 必须逐字等于原字幕。
- 若字幕文本、句界或时间码需要修改，应先走内容校对流程，不能把修改伪装成样式优化。

## 先拆参考，再定规则

在完整渲染前保存一份 `style-guide.md`，至少记录：

1. 基础字幕的字体、字号、颜色、描边、位置和每行字数；
2. 强调色、强调词长度、每块强调数量及相邻块密度；
3. 哪类词触发强调，哪些块明确不强调；
4. 是否存在放大、弹跳、底框或逐字卡拉 OK；参考没有的效果不得自行添加；
5. 手机端白底、浅色衣服和复杂背景上的对比度。

本地参考优先用 `ffprobe` 建立媒体基线，再按约 1 fps 生成字幕区域条带，并从开头、中段、结尾抽取原尺寸代表帧。网页参考若需要登录，只使用用户指定的系统浏览器与现有默认用户目录，并记录成功获取路径；浏览器页面能播放不等于已经取得可分析媒体。

## 语义锚点选择

每个字幕块从以下类别中选择最多一个连续短语：

1. 产品、技术或领域专名，例如 AI、SaaS、Agent、API；
2. 该句不可替代的业务对象或核心名词；
3. 对比、判断、结论中的落点词；
4. 关键动作、数字、步骤或结果。

优先选择 2–8 个汉字或一个简短英文词组。以下内容通常不高亮：

- “然后、其实、就是、所以”等连接词；
- “啊、呀、嗯”等填充词；
- 一整句话或连续多处同色强调；
- 相邻字幕已经重复强调的同一概念；
- 会改变原句含义或造成夸张承诺的词。

没有合适锚点时保留普通字幕。高亮密度不是 KPI，参考视频的真实规律优先。

## 默认视觉规则

- 高亮段与基础字幕保持同一字号、字重、基线和描边，只改变一种强调色。
- 参考样式未证明需要动画时，不添加底框、缩放、跳字或卡拉 OK 扫色。
- 浅色背景必须保留足够深的描边或阴影，不能使用与背景接近的裸色文字。
- 一屏只建立一个视觉主次关系；标题、头衔和字幕不得争抢同一种强调样式。

## 样片门禁

1. 先输出 5–12 秒代表性样片，至少覆盖：普通字幕、中文重点词、英文/产品名和浅色背景。
2. 同时保存高亮清单，逐块记录原文、锚点或 `none`，便于人工审查。
3. 抽查至少 6 个时间点，验证字幕位置、对比度、句界、时间同步和高亮是否符合语义。
4. 样片获得人工确认后才允许扩展到完整成片；未确认版本必须明确标为样片或预览。

## 完整成片 QA

- 对每个字幕块执行文字拼接不变量检查；
- 比对修改前后的起止时间和块数，除非内容流程已有独立批准，否则必须完全一致；
- 检查是否出现跨句合并、错别字、额外语气词、整句着色或连续高亮轰炸；
- 在 9:16 手机尺寸抽查白底、人物衣服、信息卡和 B-roll 上的可读性；
- 完整导出后再跑 `video-qa`，发现问题即修复并重新渲染，不以脚本成功代替成片通过。
