# AI 口播编辑作业手册

仅在加工原片、精修粗剪或排查失败导出时读取。

## 推荐目录

```text
<edit-dir>/
├── project.md
├── source_probe.json
├── transcripts/
├── content_plan.json
├── content_cut.mp4
├── takes_packed.md
├── edit_plan.md
├── asset_inventory.md
├── visual_plan.json
├── assets/
├── precomposed.mp4
├── inspection/
└── <唯一名称>_final.mp4
```

原片放在目录外或保持只读引用。失败导出不删除，改用新文件名；在 `project.md` 标出 `failed`、原因和后继终版。

## 阶段 A：媒体体检

1. 用 `ffprobe` 写出 `source_probe.json`。
2. 抽查开头、25%、50%、75% 和结尾画面。
3. 检查字幕是烧录、独立轨道还是不存在。
4. 检查人声是否存在削波、底噪、明显房间混响或音画漂移。
5. 如果只做前若干秒样片，先无损或高质量截取独立测试片，不改原片。

## 阶段 B：本地转写与内容粗剪

Apple Silicon 环境优先复用共享虚拟环境中的 `mlx-whisper`，开启 `word_timestamps=True`。缺少依赖时先说明安装原因；不要因为工具缺失就假装完成逐字切点。

保存：

- 原始逐字 JSON 到 `transcripts/`；
- 按停顿分组的可读稿到 `takes_packed.md`；
- 建议删减段落、保留呼吸和理由到 `edit_plan.md`。

默认只删：明确口误、立即重复、没有语义价值的长停顿。不要为了“快”把句尾、呼吸和自然停连全部切碎。

“嗯、呃、啊、呀”等不能仅靠词表批量删除：先判断它是无语义填充音，还是承担疑问、列举、强调或自然句尾。确认删除后，把绝对源时间码、逐字内容和理由写入 `content_plan.json`：

```json
{
  "version": 1,
  "source": "/absolute/path/to/source.mp4",
  "output": "/absolute/path/to/content_cut.mp4",
  "fps": 30,
  "join_transition": 0.04,
  "cuts": [
    {"start": 10.36, "end": 11.10, "transcript": "啊 + 空停顿", "reason": "无语义句尾口癖"}
  ]
}
```

先执行 `python scripts/render_content_plan.py /absolute/path/to/content_plan.json`。它同步剪音视频，并在连接处做极短交叉淡化；烧录字幕会随视频帧一起删除。输出完成后重新逐词转写并检查每个剪点前后至少 0.5 秒，确认目标口癖消失、相邻实词仍在、语义不变且没有爆音或吞字。对于低置信度的“啊、呀”等连续元音，ASR 可能把残余尾音吸收到前后实词，即使输出中没有独立 token 也不能直接判定通过；必须同时查看剪点附近的局部波形或频谱，确认残余元音能量已移除，并核对前后实词完整。烧录字幕可能以整句存在并跨过剪点，因此还要抽帧搜索被删字样；若画面仍显示口癖，局部遮盖旧字幕并按新时间线重建该句。只有音频和可见字幕都通过后，才能把 `content_cut.mp4` 作为 `visual_plan.json` 的 `source`。

## 阶段 C：画面设计表

先写 `asset_inventory.md`，盘点用户指定旧对话、旧项目和当前目录中可复用的画面资产。每项记录绝对路径、类型、时长、透明通道/编码、语义和是否计划使用。若存在与当前文案直接对应的透明动画却不使用，必须在 `edit_plan.md` 写明原因。

在动编辑器前先写一个简表：

| 时间 | 类型 | 口播观点 | 画面职责 | 素材 | 时长 | 进入/退出 | 验收点 |
|---|---|---|---|---|---:|---|---|
| 04.8s | `broll` | 提出第一个问题 | 具体化团队场景 | 会议画面 | 3.6s | 0.3s 叠化 | 前/混合/全显/混合/后 |
| 18.6s | `motion_graphic` | 列出三类材料 | 解释并列分类 | 透明关键词动画 | 4.4s | 分步出现/淡出 | 进入/可读/退出 |

每段素材都要有明确职责。若删掉该素材不影响理解，也不改善节奏，它大概率只是装饰，应减少。

### 把文案拆成可执行镜头

先按语义而不是按句号拆分：冲突、证据、方法、限制、结论分别判断画面职责。每个镜头只解决一个问题，并记录在粗剪后的输出时间线上。

推荐的 `visual_plan.json`：

```json
{
  "version": 1,
  "source": "/absolute/path/to/base.mp4",
  "output": "/absolute/path/to/preview.mp4",
  "duration": 30,
  "width": 1080,
  "height": 1920,
  "fps": 30,
  "source_subtitle_mode": "none",
  "max_broll_ratio": 0.35,
  "min_speaker_gap": 1.0,
  "subtitle": "/absolute/path/to/captions.srt",
  "visuals": [
    {
      "start": 4.9,
      "end": 7.3,
      "kind": "broll",
      "layout": "card",
      "asset": "/absolute/path/to/scene.mp4",
      "role": "把抽象观点具体化",
      "transition": 0.3
    }
  ]
}
```

`source` 应是已经完成内容粗剪的口播主线。`visuals` 中的时间码均指这条主线；素材可以是图片或视频。`kind` 必须是 `broll` 或 `motion_graphic`：前者负责场景和操作，后者负责关键词、分类、对比、因果与流程。`layout` 可为 `full`、`card` 或 `overlay`；动态图形默认 `overlay`，B-roll 默认 `full`，需要保留真人与烧录字幕时使用 `card`。旧计划缺少 `kind` 时校验器会按 `broll` 兼容处理并发出警告。生成素材前先锁定统一的环境、色温、镜头语言和禁用项，再逐镜头改变主体，不要让四段画面像来自四个不同账号。

`source_subtitle_mode` 必须根据抽帧填写为 `burned`、`soft`、`none` 或 `unknown`。源片为 `burned` 时不要再传 `subtitle`，否则播放器或编辑器可能出现双层字幕。

### 首尾帧与生成视频的使用边界

- 一张静态图加缓慢推拉：成本低、稳定，适合文件、场景和概念说明；如实称为“图片动效”。
- 首帧加尾帧生成动态镜头：适合需要明确运动方向的场景；首尾主体、视角和光线必须一致。
- 只给提示词生成视频：仅用于氛围镜头，最容易出现人物、手部、文字和空间连续性错误。
- 培训类账号少用陌生 AI 人物作为主角；真实录屏、匿名材料和本人出镜更能建立可信度。

镜头通过标准：语义对应、无虚构数据、无品牌水印、无不可控文字、人物与空间没有明显畸变。未通过时替换该镜头，不要靠快速转场掩盖。

## 阶段 D：编辑器路由

### 剪映原生路线

适合简单钩子、字幕、少量 B-roll、降噪和免费导出。使用独立草稿，先把主片放到时间线，再按计划添加素材。

本机连接失败时可使用明确应用路径：`/Applications/VideoFusion-macOS.app`。文件导入优先使用应用菜单和精确绝对路径。旧版素材拖拽无效时，检查素材卡片右下角的“添加到时间线”入口；操作超时后重新连接应用并检查时间线，不要盲目重复点击。

### Premiere 路线

适合用户明确指定 PR、多轨精确调整、关键帧、复杂音频处理或需要可移交 `.prproj`。必须新建独立工程，使用原片参数建立序列，保存后再加工。若 GUI 自动化持续无法可靠选中轨道、时间线或导出目标，停止假装完成，改走可验证的混合路线或报告具体阻塞。

### 混合路线

适用于旧版编辑器不稳定但仍要求生成剪映草稿和由剪映正式导出的情况：

1. 依据 `asset_inventory.md` 与 `edit_plan.md` 用确定性工具预合成 B-roll、透明动态图形与 0.2–0.4 秒透明度叠化。
2. 直接映射原片连续音频，避免每段重新编码导致声音断裂。
3. 验证预合成文件的关键中点和所有转场。
4. 新建空白剪映草稿，仅导入这个预合成文件并加入时间线。
5. 在时间线缩略图中确认口播与各段素材均出现。
6. 用唯一文件名从剪映导出，再对剪映终版重新验收；预合成验证不能替代最终导出验证。

对已经准备好的图片/视频素材，可先执行：

```bash
python scripts/validate_visual_plan.py /absolute/path/to/visual_plan.json
python scripts/render_visual_plan.py /absolute/path/to/visual_plan.json
```

合成脚本会保持源音频连续、为每段 B-roll 添加透明度叠化，并可选择烧录 SRT。它不会自动判断文案事实，也不会替代人工检查镜头语义。

若 FFmpeg 没有 `subtitles` 滤镜，脚本会将 SRT 封装为 `mov_text` 软字幕并打印降级提示。该文件可用于流程验收，但上传平台前仍应在剪映/PR 生成可见字幕；不能把“存在字幕轨”说成“字幕已经烧录”。

## 阶段 E：自然节奏

- 开头 0–3 秒只传达一个具体冲突或结果。
- 关键观点出现时再切画面，普通连接句留真人出镜。
- 相邻 B-roll 之间至少留出真人画面，除非正在演示一个连续流程。
- 默认把真人作为视觉主线，B-roll 总占比控制在 20%–35%；动态图形另行统计，避免用“B-roll 未超标”掩盖全程被卡片覆盖。总视觉覆盖过密时应删减而不是缩短真人回场。
- 字幕已经烧录时，不重复叠一套字幕。
- 默认不加背景音乐、花哨特效、滤镜和美颜；音频处理必须能说明实际启用项，不能把变声冒充人声美化。

## 阶段 F：失败症状与处理

| 症状 | 结论 | 下一步 |
|---|---|---|
| 只有原口播，没有 B-roll | 时间线或导出没有采用合成结果 | 检查中点帧，换唯一文件名重导 |
| 文件很小、黑屏或媒体不支持 | 不可交付 | 保留失败文件，检查素材编码并新建草稿 |
| UI 显示导出成功但文件不可读 | 不可交付 | 用 `ffprobe` 定位输出，重新导出 |
| 时长明显变短或变长 | 时间线范围错误 | 对比源时长、序列终点和音频尾部 |
| 画面是硬切 | 不能声称有过渡 | 检查每个入口和出口的三帧，补叠化 |
| 孤立单帧出现整屏重复、分块平铺或马赛克 | 可能是并行渲染污染，不能直接归因于转场或素材 | 导出异常区间全部帧，并与同 Composition 的单帧 still 对照；still 正常时用系统 Chrome 和 `--concurrency=1` 渲染短测试片，通过后以相同设置重渲染全片并完整解码 |
| 有 B-roll 但缺少计划中的关系/流程动画 | 视觉语法不完整 | 回查 `asset_inventory.md`，补 `motion_graphic` 而不是再加通用素材 |
| 字幕出现同音错字、跨句合并或与画面错位 | 文字时间线失真 | 回到原片句界，按专有词表逐项校对字幕、卡片和动画；修正后重抽关键帧 |
| 购买/会员按钮取代导出 | 仅完成草稿 | 停在付款前，报告未交付成片 |

## 阶段 G：最终验收矩阵

1. `ffprobe`：时长、尺寸、码率、视频/音频编码、声道。
2. 开头、正文、结尾：确认不是黑屏、错误版本或只导出局部。
3. 每个 B-roll 中点：确认素材正确、没有拉伸、没有无关文字。
4. 每段动态图形：检查进入、信息稳定可读和退出；流程动画还要检查步骤顺序。
5. 每个淡入淡出：至少前帧、混合帧、全显帧；必要时再检查退出三帧。
6. 音频：从开头到结尾都有音频流；在剪点附近试听或检查波形连续性。
7. 字幕与画面文字：保持原片句界，逐项核对专有词、易错同音词和语气词删点；同一词在字幕、卡片和动画中必须一致。
8. 路径：原片、草稿、终版、验收图和 `project.md` 均为绝对路径。
9. 结果用语：只有全部通过才称“终版”或“已交付”；草稿、预览、预合成和导出候选必须分别命名。

状态升级规则：

- `planned → draft`：镜头计划校验通过且合成文件产生；
- `draft → preview-verified`：规格、开中尾、全部 B-roll 中点和转场帧通过；
- `preview-verified → final-verified`：完整范围独立导出，字幕、人声、结尾和目标平台规格再次通过。
