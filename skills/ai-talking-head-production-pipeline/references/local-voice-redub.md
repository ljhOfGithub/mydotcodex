# 本地免费本人音色重配

适用于用户希望保留本人声音，但不依赖长期口语训练来改善普通话清晰度、语气、停顿或短视频节奏。这里的目标是制作可比较、可回退的试听与成片音轨，不是认证普通话等级，也不是克隆未经授权的他人声音。

## 先区分需求

- 只要求降噪、去混响、均衡或压缩：保留原声做音频修复，不启动音色克隆。
- 需要纠正错读、去除无意义语气词或重新组织语气：使用“修订文本 + 本人音色克隆”的重配路线。
- 只做声音测试：交付独立音频或明确写着“未做口型同步”的试听视频，不得冒充完成的视频剪辑。
- 完整成片：必须在声音确认后重新生成字幕，并处理口型、B-roll 或动态图形遮挡。

只使用用户本人的声音，或已明确获得授权的声音。云端方案会上传声音时必须提前说明；本地路线默认不上传参考音频。

## 已验证的 Apple Silicon 路线

优先使用 MLX 版 Qwen3-TTS Base：

- 模型：`mlx-community/Qwen3-TTS-12Hz-0.6B-Base-bf16`
- 能力：`ref_audio + ref_text` 本人音色克隆；Base 模型不等于带情绪指令的 CustomVoice。
- 运行方式：优先隔离依赖，避免为了 `mlx-audio` 跨大版本升级已有 Whisper/Transformers 环境。

安装前先运行依赖预检。若最新版 `mlx-audio` 要升级共享环境的核心包，使用类似下面的隔离命令，不修改共享 `.venv`：

```bash
uv run --isolated --python 3.11 \
  --with mlx-audio==0.5.8 \
  --with soundfile \
  python /absolute/path/to/generate.py
```

模型版本、依赖约束和缓存大小会变化；执行时重新核验磁盘、包版本和模型卡。首次下载可能耗时，后续复用本地缓存。不要把一次成功的版本号永久解释成唯一可用版本。

## 禁止预设说话人转本人音色

- 禁止使用 `Dylan` 或其他第三方预设说话人先生成表演轨，再通过 CosyVoice、voice conversion 或类似方法套用本人音色。这类串联会保留源说话人的口音、咬字和说话习惯，不能作为本人自然重配候选。
- 需要加强轻重、长短和缓急时，只在本人原声或直接本人音色克隆上，通过逐句分段、标点、候选筛选、局部语速和停顿设计完成。
- 直接本人音色克隆若出现机械感、陌生地域口音、读出指令、重复正文、只说半句或新增语气词，立即判定当前方案失败。保留失败产物供审计，回退到本人原声精修，或另做新的直接克隆短样；不得改用预设说话人中转。
- 所有新声音先交付独立短音频试听。用户确认“像本人且语气可接受”之前，不得继续做字幕重建、口型同步或完整视频替换。

## 参考音频与文本

1. 从原片选择约 8–15 秒、单人、无背景音乐、少混响、没有错读的连续语音。
2. 转成单声道 WAV；24kHz 可作为 Qwen3-TTS 输入的稳妥工作格式。
3. `ref_text` 必须准确覆盖参考音频中的全部口播。错字、漏字或多出未覆盖语音都可能导致音色漂移、尾部重复或失控生成。
4. 专有词必须人工确认。ASR 把“脱敏”识别成“脱名”时，参考文本和目标文本都使用人工确认后的正确词。
5. 保存参考时间段、参考稿、目标稿、模型和输出路径到 `project.md`；不得覆盖原片。

## 修订目标稿

- 以原话和原句界为事实基线，只修正明确错读、口误和语义为空的“啊、呀、嗯、呃”等填充音。
- “等等”、列举中的语气助词或承担态度的句末词可能有语义，不能按词表盲删。
- 不为追求流畅擅自增加观点、案例、数据或承诺。
- 使用标点和分句表达停顿、对比和重音；Base 克隆不具备与 CustomVoice 相同的自由情绪指令能力。
- 除语气词外，逐句检查起音失败、半词重复、拖音和超过约 0.35 秒的句内异常停顿，并记录到 `cadence_review.json`。不能因为 ASR 没有输出重复 token 就判定“没有卡顿”。
- 需要更有短视频节奏时，按钩子、解释、转折、结论和 CTA 分段设计语速与停顿；Base 模型不支持情绪指令时，使用标点、分句、多候选选择和分段级节奏处理，不得虚称启用了不存在的“激情”参数。

## 先做 A/B/C，不直接重配整片

从同一段约 20–30 秒内容制作同响度试听：

- `A 原声`：保留原发音和原语气，作为事实基线。
- `B 自然重配`：使用修订文本和本人音色直接生成，判断发音、音色、信息密度和自然度。
- `C 节奏匹配`：把 B 调整到接近原时长，只用于判断与旧画面的时间关系；全局拉伸容易拖慢节奏或产生处理感，默认不作为最终音轨。

`B`、`C` 是固定含义；实验轨必须使用 `experiment-*` 命名，不得把两个提示词版本冒充 B/C。

用户明确认为 B 更好时，后续从 B 继续迭代，不得静默改选 C。最终版本优先按句重新生成并设计停顿，而不是把整段 B 全局拉伸到旧视频时长。

### 此工作区的持久选择

- 用户已选择 `B 自然重配` 作为完整真人口播的默认正式声音。后续完整成片直接从 B 继续，不重复要求选择 A/B/C，也不得因制作方便静默恢复原声。
- 只有用户在当前任务明确要求“保留原声”时才允许终版使用 A；短样片、视觉测试或诊断可以暂用原声，但必须显著标注“未重配音色”。
- 该默认仅适用于用户本人的授权声音，不扩展到其他人的声音克隆。

## B 到正式音轨

1. 按自然语义拆成句或短段，保持同一参考音色和术语表。
2. 对问句、转折和结论分别生成候选；通过标点、分句和候选选择控制节奏。
3. 目标是保留 B 的清晰与紧凑，同时恢复必要的呼吸和情绪起伏。不要固定套用某个语速百分比；以当前素材的原声、参考账号和用户选择为准。
4. 句间拼接保留自然停顿并做短淡入淡出，避免爆音。
5. 最终音轨确定后再重建字幕时间码。不得继续沿用原音频字幕，也不得为了排版合并原本不同的句子。
6. 真人嘴部清晰可见时，逐句检查口型偏差。无法可靠同步的区间使用有语义的 B-roll、资料画面或动态图形覆盖；不能用无关贴图掩盖问题。

## 验收

至少完成以下检查：

1. 对 B 和候选正式音轨做逐词二次转写，与目标稿对照；漏句、错词、目标填充音残留和尾部重复均为失败。
2. A/B/C 使用同一响度基准再比较，避免“更响所以更好”。试听比较时可统一到约 `-18 LUFS`，真峰值不高于 `-1.5 dBTP`；正式平台母带仍遵循主流程的最终混音标准。
3. 报告每版时长和相对语速。生成版显著缩短时，先判断这是更有信息密度，还是快到失去自然呼吸。
4. 比较响度动态范围。动态范围明显低于原声通常意味着更平稳，也可能意味着语气更扁；只能作为提示，不能代替用户试听。
5. “二次转写正确”只证明内容清楚可识别，不能据此声称普通话达到播音、考试或专业认证等级。
6. 试听视频必须标注是否已做口型同步。只有最终音轨、字幕、画面覆盖/口型和独立导出全部通过，才可标为 `final-verified`。
7. 必须人工试听音色身份、地域口音、咬字和说话习惯；出现明显不像本人或陌生地域口音时直接失败，不能由文本相似度、无填充词或音高指标覆盖。

完整项目还必须保存 `voice_delivery.json`，并运行 `../scripts/validate_voice_delivery.py`。完整成片仍使用原声、缺少正式重配音轨或字幕文件、或 `final-verified` 时口型状态仍为 `not_synced`，校验器必须失败。
