# Team UI Style

在现有页面上做可审查的增量样式修改，保持原有 UI/UX 语言和交互行为。

## Target

用户指定的现有页面、路由、HTML 文件或组件；用户要求全站时，覆盖项目中全部可达页面和角色视图。

## 硬性约束

- 必须先检查目标页面实际渲染出的 HTML/DOM，并定位生成它的模板或组件；不得仅凭截图、描述或新建静态 mockup 替代原页面。
- 如果无法获得原页面 HTML/DOM 或无法确认对应源码，停止实现并明确说明缺少什么，不猜测路径、框架或配置。
- 直接修改现有模板、组件和样式层，优先复用当前设计 token、组件、类名、布局、断点和主题机制；不引入第二套 UI 框架。
- 保持改动小且局部。不得大幅改变原始视觉语言、信息层级、导航结构或核心 UX 路径；除非用户明确要求，不重写页面，不大幅调整 DOM 层级，不使用全局 reset 或宽泛选择器影响其他页面。
- 修改方案必须能以局部 class、token、组件变体或少量模板调整方便地应用回原代码。如果必须替换设计系统、重建主要 DOM 或重做交互流程，停止该方案并提出更小的兼容版本。
- 默认保留 `id`、`name`、ARIA 属性、`data-*`、测试选择器、表单语义和事件绑定。确需变更时，先检查所有调用方并同步测试。
- 成品必须可交互，不得把真实控件替换成图片、画布或只展示外观的静态元素。
- 交互效果必须在运行中的真实页面通过用户级操作采集。只检查源码、事件绑定、组件属性或直接调用处理函数，不算交互效果已录入。
- 必须采集范围内每个可发现控件的全部独立、用户可见状态转换，而不只是下拉框或所谓关键路径。每个控件和状态转换都必须标记已采集、失败或受阻，不得抽样后声称全部完成。
- 需要全页面覆盖时，必须建立可核对的页面矩阵并逐页录入；不能只依赖导航菜单、截图目录或测试用例名称推断覆盖完成。
- 可以在需要时启动项目已有的开发或测试流程并实际点击 UI。任何可能提交、发送、删除、支付或影响真实用户的操作，只能在隔离测试环境或获得当次明确授权后执行。
- 可以读取当前任务已授权数据库中的实际数据来选择代表记录并验证真实页面状态，默认使用只读、最小范围查询；只有在确认连接的是本地或专用测试数据库后，才可创建合成测试数据。不得向生产库写入，不得把真实个人或学生数据复制为 mock 数据。

## 工作流

### 1. 建立原页面基线

- 确认真正的项目目录、路由、入口组件和样式来源，不把素材目录当源码目录。
- 在修改前打开页面，检查 DOM、计算样式、响应式布局和当前交互；记录用户要求涉及的区域与状态。
- 检查项目已有的组件库、设计 token、CSS 组织方式和测试命令。只使用仓库中可验证的配置。
- 需要实际操作时，使用可用的浏览器控制或项目 E2E 工具打开页面、点击控件和观察 DOM；登录态、角色和环境必须来自当前任务允许的测试配置。

### 2. 全面录入 UI 页面

- 从路由配置、页面目录、导航入口、重定向、角色/权限分支和现有 E2E 清单交叉生成页面矩阵，不遗漏隐藏入口、动态路由和无导航页面。
- 矩阵至少记录路由、页面源码、进入方式、适用角色、所需数据、交互控件总数、独立状态转换、响应式断点、交互证据和录入状态。
- 对动态详情页优先使用任务范围内实际数据库中的代表记录；没有合适记录时再使用合成测试数据。对同一源码但视觉不同的空、正常、加载、错误、禁用、权限拒绝状态分别录入。
- 实际访问每个范围内页面并核对最终 URL、页面标识和关键 DOM。弹窗、抽屉、菜单、标签页和折叠区等非独立路由界面，通过点击触发后作为交互状态录入。
- 结合语义 DOM、ARIA role、`tabindex`、可见控件、源码事件绑定和动态渲染结果枚举全部交互，不只扫描 `button`。覆盖链接、按钮、表单输入与校验、选择器、菜单、标签页、弹窗、抽屉、气泡、折叠区、搜索、筛选、排序、分页、表格操作、上传、拖放、滑动、滚动、无限加载和异步反馈等实际存在的类型。
- 对每个控件实际触发其支持的点击、悬停、聚焦、键盘、触控、输入、拖动或滚动方式，记录操作前、操作中和操作后的可见状态、焦点、ARIA 状态、选中值、URL、内容、加载与成功/失败反馈；按需保存截图、浏览器 trace 或测试证据。
- 交互后出现的新菜单、弹层、字段、按钮或页面区域也要加入清单并继续采集，直到没有新的范围内控件或独立可见状态。用已访问的“控件 + 状态”去重，避免循环操作。
- 下拉框只是普通示例：应采集关闭、展开、选项高亮/焦点、选中值更新、收起，以及支持的 `Escape`、外部点击、方向键与 Enter/Space；其他每类控件也必须按其行为采集全部独立状态转换。
- 不要求穷举多个无关控件状态的笛卡尔积，但共享状态会改变另一个控件的可见性、可用性或结果时，必须采集该组合变化。
- 若某页因权限、数据或环境问题无法打开，将其标为未录入并保留原因；不得把源码存在或自动化脚本通过等同于页面已录入。
- 为每个录入状态保存可核验的状态指纹，至少包含最终 URL、角色、active Tab/选中导航、主要 heading、可见 dialog/drawer 和关键 DOM 标识。文件名、计划中的状态名或“点击已执行”不能代替状态指纹。
- 完成前把页面矩阵与实际快照 manifest 做一对一核对：状态指纹与矩阵标签不符、两个不同条目产生相同指纹、交互有通过记录但没有对应快照、或 blocked 项被计入已录入时，必须使完整性检查失败并修正或如实降级。

### 3. 准备页面状态与数据

- 可以直接读取当前任务已授权环境中的实际数据库数据，用于确认记录关系、选择代表页面和呈现真实内容；先核对环境与访问范围，只查询当前页面所需的字段和少量记录，不批量导出。
- 实际数据默认只读，不在报告、日志或截图中暴露密码、token、联系方式、学生身份或其他不必要的敏感字段。
- 实际数据没有覆盖所需状态时，优先使用项目已有 fixture、factory、seed、测试 API 或后台入口；它们仍不足时，才在本地或专用测试库创建最小合成数据。
- 写入前明确核对环境标识、主机和数据库名，确认不是生产库；无法确认时停止数据库操作。
- 按外键、枚举和业务约束创建最少量的合成数据，使用可识别的测试前缀并记录新增表、记录 ID 和关联关系。不得覆盖或删除既有数据。
- 不输出连接串、密码、token 或真实敏感字段。测试结束后只按明确记录处理当前任务新建的数据，并遵守项目的清理流程。
- 通过页面和数据库后置查询共同确认数据状态；数据库中存在记录不等于 UI 页面已成功覆盖。

### 4. 制定兼容修改

- 把新样式映射到已有颜色、字号、间距、圆角、阴影、层级和断点；新值仅用于现有系统无法表达的明确需求。
- 优先增加或调整局部 class、组件变体或 token；避免内联样式、`!important` 堆叠和依赖脆弱 DOM 层级的选择器。
- 保持信息层级、导航位置、术语、反馈模式和核心用户路径一致。需求与现有 UI/UX 冲突时，指出冲突并采用最小偏离方案。
- 修改前记录将复用的 DOM、组件和 token，修改后逐项核对；出现无法通过局部补丁兼容的变化时回退该变化，而不是扩大重构范围。
- 对交互元素同时设计并实现适用的 default、hover、focus-visible、active、selected/expanded、disabled、loading、error 状态。

### 5. 增量实现

- 在原模板或组件上修改，保留现有数据流、事件处理、表单提交、路由和异步状态。
- 新增交互时沿用项目已有事件和状态模式，并提供键盘操作；触控目标和小屏布局不得退化。
- 行为发生变化时补充最小的单元、组件或端到端测试；纯样式变化至少验证真实页面和关键状态。
- 可以保持开发服务器或测试观察模式运行，在当前真实页面通过热更新小步调整 UI；每次变化后重新操作受影响交互，不以热更新成功代替行为验证。
- 不顺手重构无关代码，不格式化无关文件，不安装依赖，除非用户明确授权。

### 6. 验证

- 使用项目已有命令运行与改动最相关的检查；先从脚本或配置中确认命令，不臆造。
- 在真实页面对修改前后的目标区域进行比较，并至少验证默认尺寸、小屏尺寸和项目已有的相关断点。
- 实际操作受影响的控件，覆盖鼠标、键盘及适用的触控路径；检查焦点、弹层、滚动、表单、加载与错误反馈。
- 对照交互清单复放每个控件的全部独立状态转换，确认采集证据显示了预期结果；只有操作动作而没有可观察结果或证据时，标为未录入。
- 检查改动范围外的邻近区域，确认没有全局样式泄漏、布局位移或交互回归。
- 全页面任务结束前对照页面矩阵复查所有角色、动态路由、关键状态和断点；逐项标记已通过、失败或未录入。
- 对快照执行重复与错标检查；不能用同一 active Tab/heading 的重复快照充当两个不同页面，不能仅按文件数量声称覆盖完成。
- 无法运行的验证必须列为未验证项；截图相似不等于交互通过。

## 完成标准

- 改动落在原页面真实 HTML/DOM 的源码链路上。
- 视觉结果沿用原 UI/UX 系统，没有大幅改变视觉语言、信息架构或核心操作路径，并能以局部补丁方便地应用到原代码。
- 受影响的交互在真实页面可用，键盘焦点和状态反馈清楚。
- 每个可发现交互控件及其全部独立、用户可见状态转换都已在真实页面触发并记录操作、结果和证据，或具有明确的失败/受阻原因；不能用抽样控件代表全量完成。
- 全页面任务具有完整页面矩阵，每个条目都有真实访问证据或明确的未录入原因。
- 改动文件少且范围明确；相关测试通过，或未验证项已如实报告。

## 输出格式

```markdown
## UI Style Report

### 原页面依据
- 路由/页面：
- HTML/DOM 来源：
- 复用的组件或 token：

### 已修改
- [文件] — [局部样式或交互变化]

### 页面录入
- [路由/状态/角色] — [页面源码] — [已录入/失败/未录入]

### 兼容性与交互
- [断点/主题/状态] — [验证结果]
- [鼠标/键盘/触控路径] — [验证结果]

### 交互效果
- 覆盖汇总：[发现控件数] / [状态转换数] / [已采集] / [失败] / [受阻]
- [页面/控件/定位依据] — [交互类型与实际操作] — [操作前→操作中→操作后] — [已采集/失败/受阻] — [截图/DOM/trace/测试证据]

### 测试
- [命令或手动路径] — [结果]

### 页面数据
- [环境/实际数据或合成数据] — [非敏感记录标识] — [页面验证结果]

### 未验证
- [项目] — [原因]
```
