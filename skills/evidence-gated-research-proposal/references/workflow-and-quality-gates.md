## 1. 输入与权威文件

开始前列出：

- 用户指定的 Word 模板和所有格式要求；
- 当前权威 proposal Word；
- 当前权威 Markdown；
- 历史快照、MANIFEST 或入口文件；
- `paper-context.md` 和相关全局论文节点；
- 用户指定的个人经历来源，包括 prior chat，而不是只看 PPT 成品；
- 应用系统的权威代码或事实来源。

若存在多个相似文档，先确认哪一份是当前权威版本。优先修订原文件；历史快照保留只读状态和清楚指向。

## 2. 主张账本

写作前维护内部表：

| 主张 | 来源类别 | 当前证据 | 可写强度 | 不能写什么 | 需同步文件 |
|---|---|---|---|---|---|
| 例：LCCA 有 ASR→评分→反馈链 | 已核实项目事实 | 代码／对话／文档 | 可作问题实例 | 不能写成方法已有效 | Word、MD |

来源类别固定为：

1. 用户明确要求或判断；
2. 已核实个人／项目事实；
3. 论文全文直接支持；
4. 助手候选解释或设计；
5. 待核实或反事实假设。

禁止把第 1、2 或 4 类改写成第 3 类。

## 3. Topic 卡

每个候选 Topic 使用同一张卡比较：

| 项 | 内容 |
|---|---|
| 一句话科学问题 | 可产生不同答案的具体问题 |
| Agent／多模态／大模型落点 | 各自不可替代的角色 |
| 最接近论文 | 直接机制近邻，不是泛背景 |
| 被近邻拿走的主张 | 明确删除的宽泛首创 |
| 候选剩余空间 | 日期化、待验证 |
| 最便宜决定性 pilot | 8–12 周内可杀死核心现象 |
| 强简单基线 | 非 LLM、规则、完整上下文等 |
| 三个独立命题 | 存在性、策略增量、行动价值 |
| kill gate | 何时停止或收窄 |
| 3–5 年条件深度 | 只有前一门通过才继续 |
| LCCA 联系 | 灵感、仪器或影子验证，不默认是边界 |

“多个 Topic”必须在科学对象、estimand 或机制上不同，不能只换标题。

## 4. 文献与新颖性审计

### 原子化主张

把“可信 Agent”拆为可检索句，例如：

- 同源派生是否导致重复计权；
- 来源图错误时方法是否仍有效；
- 某类探针是否打破被动轨迹等价；
- 诊断改善是否在冻结恢复器后改变行动；
- 当前补丁是否预测下一版本回归。

### 搜索矩阵

对每条主张至少覆盖：本项目词、直接近邻词、相邻学科词、反向词（benchmark、failure、impossibility、counterexample）。检索后做最近论文的 backward／forward citation chaining。

### 证据矩阵

| 论文 | 正式状态 | 全文状态 | 实际对象 | 支持本题什么 | 限制／覆盖什么 | 未覆盖什么 | 对主张的处置 |
|---|---|---|---|---|---|---|---|

处置使用：`KEEP_CANDIDATE`、`NARROW`、`REFRAME`、`STOP_DOMINATED`。不要因“没有完全同题标题”而保留。

### 检索停止口径

只能写 bounded saturation：连续不同查询没有出现新的机制类别，新论文能放入既有矩阵，最近近邻的前后向引用已检查，且没有再次改变主张／基线／kill gate。仍需保留日期、数据库和遗漏风险。

## 5. 术语审计

每个专业词首次出现时填写：

| 术语 | 状态 | 平实解释 | 原始来源 | 本文操作化 | 易混边界 |
|---|---|---|---|---|---|

状态只能是：`标准术语`、`论文专用术语`、`本文工作性定义`、`解释性类比`。

重点检查：

- state 是否真的对预测或决策充分；
- active observation 与 intervention 是否分开；
- provenance、data lineage 与 causal graph 是否混用；
- confidence、uncertainty、identifiability 与 evidence sufficiency 是否混用；
- oracle、ground truth 和 verifier 是否混用；
- repair debt 是否有前瞻定义，而非事后解释；
- kill gate 是否改写为正式材料可接受的“预设停止条件”。

## 6. 研究设计

至少三条可独立推翻的命题：

1. **存在／可识别性命题**：被动证据确实不能区分某些需要不同动作的状态，而某类新证据可以。
2. **策略增量命题**：相同信息、调用、token、延迟、风险和拒绝率下，选择性策略优于固定、随机、全部读取或强模型重复调用。
3. **行动价值命题**：冻结下游恢复器或执行器后，诊断／证据改进提高任务恢复或降低严重副作用。

可选第四条检验跨模型、跨任务、跨版本或人机外部效度。

每条命题需要：处理条件、对照、主要终点、独立实验单位、预算匹配、竞争解释、最便宜补充实验和推翻结果。

## 7. 三至五年时间线

时间线写成依赖图：

```text
现象与标签成立？
  否 -> 停止复杂方法，保留测量或负结果
  是 -> 表示超越强简单基线？
          否 -> 保留 benchmark，停止复杂表示
          是 -> 主动选择在同预算下有净价值？
                  否 -> 采用固定协议
                  是 -> 做跨域、人机和时间泛化
```

第一年不能只交付日志、探针库或平台。至少要得到一项端到端结论：核心现象不存在；简单基线足够；或候选机制在严格匹配下有增量。

## 8. 个人优势、LCCA 与 Education 4.0

### 个人优势表

| 已核实经历 | 可立即开展的工作 | 减少的研究风险 | 不证明什么 |
|---|---|---|---|

避免“跨学科、工程能力强”这类无证据抽象词。

### LCCA 四步链

1. 写一个具体错误传播或人工决策例子；
2. 抽象不随教育场景变化的科学结构；
3. 用领域无关 benchmark 和非教育域承担通用验收；
4. 回到 LCCA 做授权、去标识、冻结回放或 shadow mode 的有限验证。

这里的 shadow mode 指旁路运行：系统可以生成并记录建议，但不自动写回正式成绩、反馈、生产配置或学生记录。它验证现实工作流中的可用性和风险，不等于正式部署，也不能替代伦理、隐私、授权和人因评估。

### Education 4.0

将帮助写成对象—变化—指标：

- 学生：错误归因、反馈采纳、第二轮表现、申诉／重录；
- 教师：复核时间、边界案例发现、AI 建议修改率；
- 平台／学校：严重错误自动提交率、版本追溯、审计完整性。

若结果仅来自更多拒绝、更多人工或更长延迟，不能声称净帮助。

## 9. Word 与 Markdown 生成

### Word

- 模板是版式权威；先提取页面、节、字体、段落、表格、页眉页脚与标题层级。
- 正文只放正式需要的研究目标、背景、现状、方法、时间线、可行性、影响和参考文献。
- 引用题名、年份、venue、DOI／正式入口必须核对；预印本不写成正式发表。
- 生成后 render → 逐页查看 → 修复 → rerender。

### Markdown

- 更新当前权威文件。
- 补足 Word 为控制篇幅省略的术语、论文边界、研究／工程防御、个人优势、kill gates 和导师 challenge。
- 任何新近邻导致主张变化时，同步修正前文表格、总结句、答辩稿和 MANIFEST，避免一处更新、一处仍写旧结论。

## 10. 交付检查

- 扫描四类一致性：Topic 名称、科学主张、时间线、引用状态。
- 验证 Markdown 本地链接、Obsidian 双链和标题锚点；若修改 Vault，按项目规则执行全库静态和原生点击验收。
- Word 逐页视觉检查，不以成功生成或文本可提取替代。
- 搜索“首次、尚无、证明、必然、完全、显著、因果”等高风险词，逐句检查证据强度。
- 报告本轮改了哪些现有文件、没有改哪些、检查数量、错误数和剩余缺口。
