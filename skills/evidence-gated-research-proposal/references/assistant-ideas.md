# 助手提出的候选思路、后续修正与当前边界

本文件记录助手在这组对话中提出的研究思路。它不是用户承诺，也不是持续有效的新颖性证明。凡涉及“当前文献空白”的内容，未来调用时必须重新检索和全文核验。

## 0. 四组文档与 Topic 的演化关系

1. **可信多模态大模型智能体／来源依赖证据推理**：最初承担宽泛的可信 Agent 叙事，后经文献碰撞收窄到自然跨模态来源、错误 provenance、行动价值与不可逆副作用。它是证据认知总题目的主要前身，不应继续用“可信”包住所有问题。
2. **多模态 Agent 的干预式故障诊断**：把重点从静态解释推进到主动获取诊断信息及恢复；后来确认干预只是主动验证的一类，不能单独承担全部 3–5 年立意。
3. **工具漂移下 Agent Skill 持续修复**：保持为机制和时间对象不同的独立路线，重点是自然版本漂移中的候选修复准入、拒绝、真实回滚和前瞻修复债务，不应被强行并入多模态证据 Topic。
4. **开放环境中多模态大模型智能体的证据认知与主动验证**：把来源依赖证据推理与主动验证组织为同一闭环，作为当前高层总题目；仍需用表示、策略和行动价值三个独立实验避免“两个模块拼接”。

现有文档的权威状态以项目 `outputs/MANIFEST.md` 为准；历史快照只能提供演化证据，不能与当前版本并列。未来修改任一总题目或子题时，都要检查它与另外三组文档的继承、独立或停止关系。

## 1. 曾提出的候选 Topic

### A. 多模态 Agent 的干预式故障诊断

核心思想：被动轨迹不足以区分感知、推理、工具、记忆和环境故障时，Agent 主动执行最小诊断探针，例如局部重观察、替换 ASR、隔离工具、清除记忆或固定状态重放，再根据结果选择恢复。

原始贡献设想：从“读日志猜根因”转向“通过行动获得诊断信息”。

后续文献修正：DoVer 和 REFLECT 已覆盖干预、检查点重放、验证与修复；IDI 已把根因与修复后的目标改善连接；ACDB 和最小成本干预设计已覆盖预算化实验选择。宽泛的“首次主动诊断”或“首次干预后重放”已不能讲。

可保留的窄问题：无答案 oracle、探针有噪声和副作用、不可逆动作、多故障、最小充分探针，以及冻结恢复器后诊断信息的因果行动价值。

### B. 多模态 Agent 的因果／来源证据溯源

核心思想：追踪图像、音频、文本、工具输出和记忆之间的来源与派生关系，避免把同一上游错误的多个派生结果当成独立证据。

后续文献修正：CAMA 已研究相关证据与有效独立来源数；LEDGERMIND 已提出多模态 Structured Evidence Ledger 和主动 repair。不能再声称首次发现同源重复计权、首次建立多模态证据账本或首次依据账本补证。

可保留的窄问题：自然跨模态来源、provenance 缺失／错误／伪造、来源可靠性随时间变化、账本错误时的鲁棒性，以及来源信息是否真正改变行动而非只改善解释。

### C. 工具漂移下 Agent Skill 持续修复

核心思想：工具、API、模型或规则升级后，定位旧 Skill 的失效部分，产生多个候选补丁，并决定接受、拒绝、回滚或重建，同时控制未来版本的修复债务。

后续文献修正：Repo2Skill-Evo 已覆盖真实版本跃迁中的陈旧内容定位；SkillScriptBench 已覆盖结构化局部修复和保持约束；SkillGuard 已覆盖契约监控、漂移检测和一次候选验证；SKILL.nb 已覆盖版本状态、门控、lineage 和修复负担。泛化的“首次持续修复 Skill”已不成立。

可保留的窄问题：严格时间冻结的自然多版本链、同候选池的选择性部署、隐藏行为、实际回滚、失败原因混杂，以及能前瞻预测后续回归的修复债务。

### D. 语义状态重建

核心思想：多模态 Agent 在工具调用、界面更新和异步反馈后，重建“环境实际上发生了什么”，而不是沿用自然语言轨迹中的假定状态。

主要风险：可能被 belief-state estimation、world-model、GUI state tracking 或 observability 文献直接覆盖。必须先定义与标准部分可观察状态估计不同的 estimand 和决定性实验。

### E. 证据校准的承诺与可逆行动

核心思想：Agent 在证据不足时不应过早承诺；高风险行动需要证据门、暂缓、批准、事务式提交或可逆机制。

后续文献修正：Selective Autonomy、Premature Commitment、MemTX 和 Cordon 已分别覆盖选择性自治、早承诺、记录级 action-safe 门和工具事务。剩余空间只能位于证据充分性与具体动作提交之间的接口，以及事务边界外不可逆后果。

### F. 反事实记忆治理

核心思想：当上游证据或结论被纠正时，识别哪些记忆、摘要、评分和后续计划应失效、重算或撤回。

主要风险：可能与 memory editing、belief revision、truth maintenance、provenance invalidation 和 transactional memory 直接碰撞。必须用真实级联影响和行动结果证明区别。

### G. 预算约束的主动多模态感知

核心思想：在 token、时间、工具调用和风险预算下，选择最有价值的下一种模态、传感器或查询，而不是无条件读取所有模态。

后续文献修正：ACDB、CAMA、LEDGERMIND 和 Ask the World Before Acting 已覆盖预算内实验、证据恢复和环境探测。剩余主张必须同时涉及来源依赖、机制区分、探针扰动或真实恢复价值。

## 2. 合并后的高层 Topic

建议总题目：**开放环境中多模态大模型智能体的证据认知与主动验证**。

提出该题目的原因：来源溯源回答“当前判断依赖哪些证据、还剩什么歧义”；主动验证回答“证据不足时下一步获取什么新信息”；验证结果更新同一表示，并影响执行、恢复、暂缓、撤回或人工交还。干预式故障诊断是主动验证的一类，不再承担全部 3–5 年立意。

### 四个研究目标

- **O1 来源感知的多模态证据表示**：证据内容、模态、来源、父证据、变换、版本、时间和生命周期。
- **O2 行动条件化的充分性与可辨识性**：当前信息能否区分那些需要不同正确动作的候选状态。
- **O3 成本与风险约束的主动验证**：重观察、独立查询、重放、澄清、人工复核或干预的选择。
- **O4 从验证结果到执行和恢复**：提交、暂缓、撤回、局部恢复、回滚或交还。

### 四个可独立推翻的命题

- **H1**：在内容和 token 匹配时，同源派生证据会造成系统性过度计权。
- **H2**：来源感知表示能识别与行动相关的未决歧义，而不只是生成更好解释。
- **H3**：在同候选、同调用、同 token、同延迟和同风险预算下，选择性验证优于固定检查、随机验证、全部读取和重复调用强模型。
- **H4**：冻结恢复器后，更正确的证据／诊断信息能提高恢复成功或降低严重副作用。

每个命题可独立失败。H1 失败时放弃复杂来源建模；H3 失败时保留固定协议；H4 失败时只能主张测量或解释价值。

## 3. “证据状态”的术语修正（助手后续判断）

本节是助手在后续全文核对后形成的方法论判断，不是用户因举出“证据状态”这个未解释名词而提出的专项要求。用户的原始要求是普遍解释专业词；是否采用下面的拆分，仍应由具体 Topic、文献和实验需要决定。

早期文档把“证据状态”写成统一对象，但全文核对显示：

- POMDP 的 **belief state** 是给定历史后的潜在环境状态分布；
- **information state** 是支持后续动态决策的充分历史摘要；
- LEDGERMIND 把 Structured Evidence Ledger 当作 canonical runtime／trajectory state；
- Omni-Decision 使用 `typed evidence state`，写成未解决需求、事实槽、确认的证据和冲突；
- CAMA 正式定义的是包含记忆切片、provenance 图、潜在证据槽、有效独立来源数和后验的 recovery state；
- AgentRCA 没有定义 evidence state，只维护候选排序和支持／反对证据。

因此未来写作应使用“本文定义的来源感知证据状态表示”，而不是暗示存在统一标准理论。建议拆分为：

```text
Evidence representation E_t = (records, provenance graph,
                               candidate hypotheses, lifecycle/quality status)
Identifiability test I(E_t, candidate actions)
Verification policy pi(action | E_t, budget, risk)
```

“下一步获取什么证据”属于策略，不属于状态本身。除非证明该表示对未来奖励或行动是充分统计量，否则不要把它等同于 belief state 或 information state。

## 4. 文献碰撞后的当前研究姿态

截至 2026-10-23 的直接近邻提示：

- CAMA、LEDGERMIND 已拿走同源证据和证据账本的宽泛主张；
- DoVer、REFLECT 已拿走干预—重放—修复的宽泛主张；
- Ask the World Before Acting 已拿走探测与行动共享预算的宽泛主张；
- MemTX、Cordon 已拿走提交门、事务和局部回滚的宽泛主张；
- SkillGuard、SKILL.nb 已拿走 Skill 契约监控、版本化门控和修复负担的宽泛主张。

当前只能把以下内容视为候选剩余空间，而非已证实创新：

1. 来源记录不完整、错误或伪造时的证据推理；
2. 自然跨模态共享原因，而非合成文本重复；
3. 无 oracle、多故障和不可逆副作用下的最小充分验证；
4. 证据或诊断信息对最终行动损失的边际因果价值；
5. 时间冻结的自然多版本 Skill 部署与可预测修复债务。

这些结论是日期敏感的。未来不得直接复用“尚未覆盖”，必须重新搜索正式 venue、预印本和引用网络。

## 5. LCCA 与 Education 4.0 的建议叙事

LCCA 可提供具体灵感链：原始录音 → ASR → 分项评分 → 反馈 → 教师复核。ASR 错误可同时传播到分数和反馈，形成表面一致但同源的证据；系统可选择局部重听、独立 ASR 或教师核查。

通用抽象是：多个观察可能共享来源，当前状态可能不可辨识，验证有成本和风险，行动必须受证据充分性约束。

通用主张应先在领域无关和非教育任务中验证。只有通过后，才回到 Education 4.0 场景评价学生错误归因、反馈采纳、第二轮表现、教师复核时间、严重错误自动提交率和审计完整性。

“LCCA 影子案例”不是把新方法直接投入正式教学决策。它指系统在真实或冻结回放工作流旁路运行，记录诊断、证据、建议和拒绝状态，供教师或研究人员查看，但不自动改变正式成绩、学生反馈、生产配置或学生记录。只有取得授权、伦理与隐私条件，并证明净收益后，才讨论更强部署。

## 6. 已发生的书目与证据状态纠正

这些纠正本身不是研究贡献，但必须防止未来 Word 与 Markdown 继续传播旧说法：

- Program Dependence Graph 的经典论文年份应按正式书目写为 1984，不沿用误写的 1987。
- Selective Autonomy、Premature Commitment、CHIEF 和 Structured Uncertainty 等条目必须以论文首页、正式索引或 arXiv 最新版本的准确题名为准，不能把描述性副标题、搜索结果简称或旧文档标题当正式题名。
- CHIEF 的正式题名核验为 *Hierarchical Failure Attribution for LLM-based Multi-Agent Systems*；“From Flat Logs to Causal Graphs...”只能在来源确有该副标题时使用。
- ACL Findings、workshop、Datasets and Benchmarks Track、arXiv 预印本与会议 main track 必须分别记录，不能仅凭会议大类把它们统一写成 CCF A 正式主会论文。
- 任何题名、年份、venue、版本、DOI 或访问状态发生纠正时，都要同步扫描 Word、Markdown、参考文献表、MANIFEST 和答辩问答中的旧表述。

## 7. 三至五年依赖图

- **0–12 个月**：测量现象、构造硬真值和强基线；前 8–12 周完成最便宜的决定性 pilot。
- **12–24 个月**：仅在现象成立后研究表示是否超越完整上下文、简单去重和规则账本。
- **24–36 个月**：仅在表示有增量后研究预算和风险约束下的主动验证与恢复。
- **36–48 个月**：仅在核心机制通过后做人机、跨域与可选 LCCA shadow validation。
- **48–60 个月**：仅在真实版本变化出现后研究时间泛化、工具漂移和治理。

时间线的价值是暴露依赖和停止条件，不是证明项目天然值得五年。
