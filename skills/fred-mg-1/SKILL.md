# fred mg 1

这是本机个人 MG 风格入口：黑白紫、粗标题与窄数字、真实媒体窗口、分层追加和独立状态反馈。实际渲染默认使用已安装的 Hyperframes。风格由参考成片分析与通用骨架适配形成，不声称取得原作者工程或拥有对方素材。

## 取得实际模板

先运行本 Skill 目录下的 `scripts/style.py info`，读取本机登记的模板工程、完整演示与逐段对应位置；运行 `verify` 校验固定基线。个人配音、角色和示例视频存放在本机独立风格库，公开 Skill 不包含这些媒体。

新项目使用 `python3 scripts/style.py init /新项目路径` 复制基线。它拒绝覆盖已有目录；不要直接改固定基线。若本机未登记，先让已有个人风格包回到本机，再用 `register /风格根目录` 登记；不能把一个同配色的新画面冒称已经用了此风格。

## 用在当前内容

- 先读 [风格与动作说明](references/style-spec.md)，再读实际模板的 `模块索引.json`、`逐段动效对照.json` 并按各场景的`template`字段和HTML脚本引用定位实际模板及动作运行库。从23场景中选当前内容需要的模块，不强制每条视频使用全部场景或151秒时长。
- 替换当前文案、实际数据、案例媒体、配音和字幕。示例预算、角色及整轨旁白属于样例，不是风格本身，也不是新主题的事实。遵守当前用户的角色、声线、原速和引擎要求。
- 实际保留并改编对象分组、错峰关系、前后状态、独立进度及切镜。根据新内容调整时窗；不把一条样片的时码变成通用规则，不用一种淡入代替不同动作。
- 复刻仍逐段对照当次参考片；原片没有的动作不因本风格含有就随意加入。风格骨架也可用于原创工作流讲解，此时按内容选择动作，不冒称原片匹配。
- 构建、检查和渲染使用模板自带命令与本机 Hyperframes Skill。实际视频核对动作中间态、文字边界、字幕和媒体；新片完成当前工作区规定的视觉及每半秒OCR检查。声音只做存在、解码和指定原速的文件检查，不安排声音批准。

当前基线原生规格为1920×1080、30fps。其他画幅需重排并验证，不能拉伸现成模板后声称已支持。

## 保存状态与来源

命名、保存和复制已经存在的模板，不需要重新渲染未改媒体。技术完成、视觉复核和用户审美认可分别记录，不把成功渲染当作完全一致。参数近似与素材替换的边界见本机模板中的 `依赖与来源.md` 和 `验收说明.md`。


## 使用独立组件

公开组件版本位于[mg-style/fred-mg-1/components](https://github.com/ljhOfGithub/mg-style/tree/main/fred-mg-1/components)，包含23个单场组件。需要单独预览、参数替换或片段渲染时，优先读取该版本的`catalog.json`和`README.md`，再使用`build.py --component ID --output 目标目录`，不要把151秒整片的其他场景一起带入。

每个导出工程只带一个模板、自己的媒体与时间线，可用其`build.py`独立重建。文字、数据、图片和视频插槽按目录约束填写；绑定字段不再同时当作普通文案，视频保持原速并保留背景源偏移，时长不足会报错。用Hyperframes实际检查和渲染，再做实际帧与半秒OCR核对。

公开仓库文件夹统一为英文，如`template`、`components`、`modules`、`presets`、`variants`、`assets`、`previews`。本机已经登记的旧个人基线仍以`style.py info`返回的实际路径及场景配置为准，不自动重命名、覆盖或重新登记旧媒体。
