# 论文精读笔记：推理链检查表

在用户现有笔记中写，不强制新建文件，也不要求所有标题。每个箭头处写清“为什么下一步由上一步引出”；若原论文没有提供这一步，把缺口明说。

```markdown
# 《论文标题》：作者如何得出结论

> 原文 PDF / 正式页面：
> 核对范围：方法、实验、限制和必要附录；尚未核对：

## 读前只补必要的背景
用一个与论文任务一致的小例子，先说明输入、Agent/模型做的事、可修改的对象和反馈。挑出理解中心问题必需的少数概念：每个概念都解释“是什么、在后文哪一步用到”，第一次出现时展开缩写。教学类比与论文实际案例分开标注。读者已懂的内容略去；不要把背景写成通用综述，也不要用术语表替代这里的就地解释。

## 术语表

> 来源：原文 PDF / 正式全文；证据等级：全文（若只有摘要或人工材料，明确改写）

| English term / symbol | 中文对应 | 类型 | 零基础解释 | 在本文中的作用与易错边界 |
| --- | --- | --- | --- | --- |
| 示例术语 | 中文对应 | 术语 / 缩写 / 符号 / n. / v. / adj. | 它是什么 | 本文哪一步用到；不要与什么混淆 |

正文第一次遇到术语时仍要解释；本表用于集中回看，不能省略。仅收录理解本篇问题、方法、实验所需的领域术语，以及真正影响阅读的 CET-6+ 词；删除普通词、引用列表噪声和空中文释义。

## 先给读者一个必须回答的现象
在什么系统和条件下，出现什么具体失败或反常结果？它会造成什么后果？

**因此接下来要问：**为什么常用解释/做法没有解决它？

## 旧解释卡在哪里
给一个最强的既有解释或基线，说明它在什么可观察条件下不足。若作者没有证明旧方法不足，标注这是作者的动机而非已证事实。

**因此接下来要问：**作者认为真正起作用的机制是什么？

## 问题—方法最小映射
先把总问题拆成能独立出现、能单独观察的最小子问题，再写对应的最小子方法。每行都回答“为什么这个改动能处理这个失败”，并紧跟能区分该作用链与替代解释的证据；无法隔离时写“联合支持”，不要硬凑一一因果。

| 最小子问题 | 对应子方法与干预点 | 为什么可能有效 | 直接证据 | 未隔离因素/边界 |
| --- | --- | --- | --- | --- |
| P1：在什么状态或决策点发生什么失败 | M1：改变哪个变量、表示、约束或操作 | M1 如何阻断 P1 | 对照、消融或论文未验证 | 还能由什么解释 |

然后抽象为可迁移结论：当条件 C 下出现机制 P，在 X 点采用原则 M，应使可观察量 O 改变；若 R 出现则停止迁移。再给一个贴近用户场景的最小试用：怎样识别 P、先试哪一步、看哪个 O。论文没有提出方法改进时，明确写“本文只诊断 P，没有对应 M”。

## 作者押注的机制与方法
用因果或功能链说明：A 怎样影响 B，方法改变哪一环。让同一个具体任务走一遍输入、更新、调用和输出。术语在首次出现处解释其作用，并保证它也能在独立术语表中集中查到。

**若这个解释正确，我们应看到：**与最强替代解释不同的可观察预测。

## 基础理论与符号到底在说什么

先写顶层对象与不变量，再解释关键符号。不要停在中文释义。

| 层 | 要回答的问题 |
| --- | --- |
| 对象 | 状态、动作、资源、观测、结果分别是什么？ |
| 操作 | 每个函数/程序读什么、改什么、输出什么？组合顺序为何重要？ |
| 假设 | 哪些状态可见、影响范围已知、操作可逆、样本独立？ |
| 理论来源 | 对应状态机、程序语义、事务、控制、因果、优化或统计中的哪类基础思想？ |
| 保证 | 哪一步是定义、恒等式、命题/定理、近似或解释？保证哪个不变量？ |
| 失效 | 隐藏状态、副作用、表示不足或分布外输入会怎样破坏保证？ |

若论文没有严格理论，明确写“概念解释，不是论文定理”。

### 基础理论的来源坐标

对每条会影响方法理解的理论线填写；不能只列术语或参考文献。

| 理论线 | 学科 / 子领域 | 最初解决的问题与工程/行业场景 | 代表论文、专著或标准 | 证据关系 | 当前论文继承/改造什么；哪里不等价 |
| --- | --- | --- | --- | --- | --- |
| 例：补偿事务 | 计算机科学 → 数据库与分布式系统 | 长事务跨多个服务，无法长期持有锁，也未必存在原子逆操作 | 作者、题名、年份、稳定入口 | `[方法内直接使用]` / `[作者直接引用]` / `[作者明确讨论]` / `[学术谱系]` / `[解释性类比]` | `w/u` 对应什么；为何通过补偿不等于逐字节回滚 |

表后让一个具体对象走完“来源概念 → 当前符号/组件 → 预期可观察后果”。代表来源不是作者灵感的证据；只有当前论文正文或参考文献明确连接时，才能写“作者直接引用/讨论”。

## 实验如何裁决
每条中心主张紧接对应实验：为什么选这些任务、组别、控制变量、指标和预算；实验改变了什么、没改变什么；它实际能排除哪种解释。接着给原文图表位置和关键结果，再写结果支持的最窄结论。

### 从 insight 到实验场景的逆向推演

对每条中心主张分别填写，不把多个不同实验揉成一个总表。

| 项 | 分析 |
| --- | --- |
| idea / insight | 现象、候选机制、最强竞争解释，以及两者预测分叉点 |
| 场景 | 为什么选这个任务、顺序、容量、分布或异常状态；是代表性场景、压力测试还是难例 |
| 对象与单位 | 研究对象、处理分配单位、观测单位、独立重复单位；是否存在伪重复 |
| 环境 | 固定的模型、提示、工具、数据版本、预算、硬件、随机种子 |
| 条件 | control / treatment / oracle / ablation 每组只改变什么、排除什么；有无混杂 |
| 执行 | 初始状态 → 分配/干预 → 行为/更新 → 最终测量；有无携带效应 |
| 指标 | 定义、分母、方向、聚合层级、重复数、区间/方差与缺失处理 |
| 结果 | 原始数值或方向；最窄结论；作者解释；仍未排除的解释 |
| 总结 | 支持强度、最便宜补充对照、推翻 insight 的结果 |

**仍不能断言：**缺少的对照、测量或跨场景证据。若论文有第二条中心主张，从新的问题开始另一条短链。
```
